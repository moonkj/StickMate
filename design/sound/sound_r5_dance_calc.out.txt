§2. macOS — 레벨이 아니라 「스트림 개방」이라 더 나쁘다
==============================================================================
  프로브: kAudioDevicePropertyDeviceIsRunningSomewhere — 불리언, 임계 개념이 성립하지 않는다.
  M-B 실측: **무음을 출력하는 스트림도 1로 잡힌다.** 즉 볼륨 0이어도 소용없다.

  원샷 상한(400 ms) + R4 링거 3.0s = 장치 개방 3.40s  vs T1 3.0s → 단독으로 춤 개시: True  (여유 +0.40s)
  성취 상한(800 ms) + R4 링거 3.0s = 장치 개방 3.80s  vs T1 3.0s → 단독으로 춤 개시: True  (여유 +0.80s)

  ★ 단발 자기발동을 막으려면 링거 < 2.20s 여야 한다(성취 클립 기준).
     그런데 R4가 링거 3.0s를 고른 근거가 «미리듣기를 1~2초 간격으로 비교하며 누르는
     조작을 한 번의 개방으로 합치기»였다. 링거를 2.20s로 줄여도 그 병합은 남고,
     간격 1.5s로 두 번 누르면 개방 4.10s ≥ T1 3.0s → 여전히 발동한다.
     ⇒ **링거의 존재 이유(병합) 자체가 T1을 넘기는 기전이다.** 노브로 못 뺀다.

§3. 자기 되먹임 루프 — 「시작음 + 종료음」을 붙이면 음악 없이 영원히 춤춘다

  가정: 시작음 400 ms + 종료음 400 ms, R4 링거 3.0s. 외부 음악은 «맨 처음 3.5초 한 번»뿐.

  [해석식]  장치 개방창 L = 3.40s
            Stop 시각  = max(L+T2, T3) = max(6.40, 8.0) = 8.00s
            재시작 주기 = Stop + T1 = 11.00s
            듀티        = 72.73 %

  [시뮬 dt=0.01]  600초 동안 Start 55회, 최빈 주기 11.02s
  [시뮬 dt=0.50]  600초 동안 Start 55회, 최빈 주기 11.0s   (실제 폴링 주기)
  [OK ] 해석식 ↔ 시뮬(dt=0.01) 주기 일치                                    =      11.0200 s  (기대 11.0 s, 허용 ±0.02)

  [OK ] 외부 음악이 3.5초뿐인데 600초 동안 계속 춤이 재점화된다                         = True  (기대 True)

  ★ T4(고착 상한 1200s)가 이걸 못 잡는다 — 매 사이클 onRun이 0으로 리셋되기 때문이다.
     T4는 «끊기지 않는 ON»만 본다. 이 루프는 스스로 끊었다가 다시 켠다.

  ★ 듀티 대조: 이 루프 72.73% vs design-motion 의도 26.97% = 2.70배
     MOTION_SPEC §26-0 #8: 춤은 SpectacleEventLock을 잡는다 → 활쏘기·그라피티·투두·포모도로
     포즈가 그 72.7% 동안 발동 불가가 된다.

  --- 음성 대조: 루프가 «어떤 링거에서도» 성립한다고 말하면 그건 틀린 검사기다 ---
    링거 3.0s → L=3.40s ≥ T1 → 주기 11.00s / 듀티 72.73%
    링거 2.6s → L=3.00s ≥ T1 → 주기 11.00s / 듀티 72.73%
    링거 2.0s → L=2.40s < T1 3.0s → 루프 없음 (기대대로)
    링거 1.0s → L=1.40s < T1 3.0s → 루프 없음 (기대대로)
    링거 0.0s → L=0.40s < T1 3.0s → 루프 없음 (기대대로)
  [OK ] 링거 0s(즉시 닫음)에서는 루프가 성립하지 않는다 — 검사기가 조건을 실제로 본다             = True  (기대 True)

§4. 「시작음만 붙인다」로 도망갈 수 있는가
==============================================================================
  종료음을 빼면 재점화 씨앗이 없어져 무한 루프는 사라진다. 그러나 잔여 왜곡이 남는다:
   - 우리 시작음이 onRun을 3.40s 늘린다 → 음악이 실제로 끝난 뒤에도
     T2(연속 OFF 3.0s) 계산이 최대 3.40s 늦게 시작된다
     ⇒ 춤이 음악보다 최대 3.40s 더 길어진다(설계값 아님, 부작용).
   - macOS [미리듣기] 버튼 1회 = 개방 3.40s ≥ T1 → **설정창에서 미리듣기를**
     **누르면 캐릭터가 춤추기 시작한다.** 사용자가 요청한 적 없는 인과다.
   - 그리고 이 왜곡은 **관측이 불가능하다** — 프로브는 «누가» 냈는지 못 말한다(§1·§2).

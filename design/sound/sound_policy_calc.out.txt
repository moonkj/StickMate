§1 마스터 볼륨 기본값
==============================================================================
  클립 정규화 목표      : -1.0 dBTP (전 클립 공통)
  볼륨 슬라이더 기본값  : 40 / 100
  -> 진폭 배율          : 0.2172  ( = (40/100)^(5/3) )
  -> 마스터 감쇠        : -13.26 dB
  가장 큰 이벤트(오프셋 0 dB) 출력 피크 : -14.26 dBFS
  OS 알림음 가정 피크                    : -6.00 dBFS
  -> 여유(headroom)     : 8.26 dB   (요구 8.0 dB 충족)
  -> 체감 크기 비       : 0.564 배 (알림음을 1로 볼 때)

  '슬라이더 절반 = 체감 절반' 성질 검산:
    슬라이더 100 -> 진폭 1.0000 (  +0.00 dB), 체감 1.0000배
    슬라이더  50 -> 진폭 0.3150 ( -10.03 dB), 체감 0.4988배
    슬라이더  40 -> 진폭 0.2172 ( -13.26 dB), 체감 0.3987배
    슬라이더  20 -> 진폭 0.0684 ( -23.30 dB), 체감 0.1989배
    슬라이더  10 -> 진폭 0.0215 ( -33.33 dB), 체감 0.0992배
    슬라이더 100 -> 50 의 체감비 = 0.4988 (0.5000 이어야 한다: OK)

  DSP 버퍼   256 샘플 -> 지연   5.33 ms, 믹서 콜백  187.50 Hz
  DSP 버퍼   512 샘플 -> 지연  10.67 ms, 믹서 콜백   93.75 Hz
  DSP 버퍼  1024 샘플 -> 지연  21.33 ms, 믹서 콜백   46.88 Hz
  DSP 버퍼  2048 샘플 -> 지연  42.67 ms, 믹서 콜백   23.44 Hz

  현재값 512 (ProjectSettings/AudioManager.asset 실측) -> 제안 1024
  콜백 빈도 93.75 Hz -> 46.88 Hz = 50% 감소
  대가: 지연 10.67 ms -> 21.33 ms (+10.67 ms)
  판정: 이 앱의 소리는 전부 UI 원샷이라 21 ms 지연은 인지 한계 아래다.
        (리듬 게임처럼 박자에 맞추는 소리가 하나도 없다 — 사운드 카탈로그 §2 전수)

  동시 발성 상한 설계값 : 3
  m_RealVoiceCount    현재 32 -> 제안 8   (설계값 대비 여유 2.67배)
  m_VirtualVoiceCount 현재 512 -> 제안 32 (설계값 대비 여유 10.67배)

§6 티어별 발동 예산 상한
==============================================================================
  티어            버스트         리필       시간당 상한       12시간 사용시     최소간격
  ----------------------------------------------------------------------
  A 직접            -          -         무제한*           무제한*   150ms
  B 유발            4       60s        60.0회           720회   150ms
  C 자율            3      600s         6.0회            72회   150ms
  M 성취            2     1800s         2.0회            24회   300ms
  ----------------------------------------------------------------------
  * A(직접)에 예산이 없는 이유: 사용자가 그 순간 스스로 누른 것이라 '예상 밖의
    소리'가 원리적으로 발생하지 않는다. 대신 최소 간격 150 ms 로 연타만 막는다.
    150 ms 간격의 이론 최대 = 6.67 회/초.
  ** B(유발)의 실제 상한은 버킷이 아니라 사람의 손이다 — 던지려면 매번 직접
     끌어야 한다. 버킷의 역할은 시간당 총량이 아니라 '한 번의 던지기가 만드는
     연쇄(던짐->구름->착지->정착)'를 4발로 자르는 버스트 제한이다.

  ★ C(자율)를 시간당 6회로 묶는 근거:
    이 앱은 이미 자율 '구경거리' 확률 10종을 전부 0으로 내린 전력이 있다
    (StickConfig: windowTheft/graffiti/desktopTidy/blackhole/windowCrash/
     archery/todoReminder/stressSulky/wanderPostIdleJump/wanderEdgeJump = 0,
     DefaultStickConfig.asset 에서도 동일 확인). 사유는 사용자 피드백
     '요청하지도 않은 구경거리가 자율 확률로 계속 떠서 ... 유저는 그게 무엇인지도
      알 수 없었다'. 눈으로 보는 구경거리조차 0으로 내려간 앱에서 귀로 듣는
      구경거리를 기본 ON 으로 두는 것은 방향이 반대다.

§8 '귀 자격 규칙' 4조건 AND — 대표 시나리오 진리표
==============================================================================
  규칙: (1)상태전이 확정 AND (2)원인이 사용자 직접조작 AND
        (3)사용자가 지금 보고 있음 AND (4)묵음조건 0건  -> 그때만 소리

  시나리오                                (1)  (2)  (3)  (4) -> 소리
  ------------------------------------------------------------------
  설정창에서 미리듣기 클릭                         O    O    O    O -> 소리남
  단축키 A 로 활쏘기 -> 명중                     O    O    O    O -> 소리남
  회의 중(마이크 ON) 단축키 A                    O    O    O    X -> 무음
  전체화면 게임 중 캐릭터 자율 착지                   O    X    X    X -> 무음
  자리 비운 사이 자율 파쿠르                       O    X    X    X -> 무음
  새벽 2시에 사용자가 장비 착용                     O    O    O    X -> 무음
  사용자가 던진 캐릭터가 3초 뒤 착지                  O    O    O    O -> 소리남
  집중 세션 중 캐릭터 자율 착지                     O    X    O    X -> 무음
  화면 꺼진 채 레벨업                           O    X    X    X -> 무음
  사용자가 보는 중 자율 창도둑(확률 0)                X    X    O    O -> 무음
  ------------------------------------------------------------------
  10개 대표 시나리오 중 소리가 나는 것 = 3 건 (30%)
  나머지 7건이 전부 '무음'인 것이 이 정책의 목적이다.

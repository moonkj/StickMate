## 1. ★ 자격 기준 — 리더 제안을 하나 고쳐서 채택한다

### 1-1. 제안된 기준과, 그것이 틀리는 정확한 지점

> 리더 제안: **"사용자가 방금 한 행동의 결과인가."**

**방향은 옳고, 단어 하나가 틀렸다.** 이 기준을 문자 그대로 적용하면
**`집중 세션 완료`가 탈락한다** — 25분은 "방금"이 아니다.
그런데 그것은 이 앱에서 소리가 가장 필요한 **단 하나의 순간**이다:
`design-systems` ECONOMY_SPEC 4-2에서 **재화가 실제로 지급되는 지점**이고(25분 = 30동전),
7-1이 **"재화 손실 방지 — 필수"**로 즉시 저장을 거는 유일한 정기 이벤트다.

하중을 받는 것은 **최근성**이 아니라 **예상 가능성**이다.
사용자는 25분 전에 **길이를 자기가 골랐다.** 그 소리는 앱이 말을 거는 것이 아니라 **답하는 것**이다.

### 1-2. 채택 — 허가 2문(AND) + 필요 1문

| 시험 | 질문 | 무엇을 막는가 |
|---|---|---|
| **P1 원인** | 인과 사슬의 **시작**이 사용자의 명시적 조작인가 | 상주 앱이 말을 거는 것 |
| **P2 예상** | 사용자가 그 소리가 날 것을 **이미 알고 있었는가** | 소리가 **놀라움으로** 정보를 나르는 것 |
| **N 필요** | 소리가 없으면 사용자가 **놓치는 것**이 있는가 | (티어를 가르지 않는다 — 아래) |

**허가 = P1 AND P2.** 하나라도 아니오면 **그 소리는 만들지 않는다.**
**N은 스위치를 가르지 않는다.** N=예인 항목은 **시각 신호 필수 등급이 올라갈 뿐**이다
(소리가 유일한 전달자가 되면 안 되므로 — `SILENCE_POLICY.md` §4-1).

> ★ **왜 P2로 바꾸는 것이 기준을 느슨하게 하는 게 아닌가**:
> P2로 교체해도 자율 착지·파쿠르·말풍선·오류·레벨업은 **전부 그대로 탈락한다** — P1에서 이미 걸린다.
> P2가 살리는 것은 **`focus.complete` 하나뿐**이고, 그것은 사용자가 시간을 직접 지정한 이벤트다.
> 즉 P2로의 교체는 **완화가 아니라 정밀화**다.

### 1-3. 후보 전수 판정 (리더가 지정한 7종을 전부 포함)

| 후보 | P1 | P2 | N | 판정 |
|---|:--:|:--:|:--:|---|
| 사용자가 누른 것 — 단축키/버튼 | O | O | – | **자격 있음** |
| 집중 세션 **시작** | O | O | – | **자격 있음** |
| ★ 집중 세션 **완료**(재화 지급) | O | O | **O** | **자격 있음 — 이 앱 최고 우선순위** |
| 집중 세션 중도 취소 | O | O | – | 자격은 있으나 **만들지 않는다**(§1-4) |
| **구매** | O | O | **O** | **자격 있음** (상점 구현 후) |
| **착용 / 해제** | O | O | – | **자격 있음** |
| 던진 뒤 착지·구르기 (사용자가 던짐) | O | O | – | **자격 있음** |
| 로데오 커서 잡기 | O | O | – | **자격 있음** |
| **자율 착지**(배회하다 떨어짐) | X | X | – | **자격 없음** |
| **자율 파쿠르 등반** | X | X | – | **자격 없음** |
| **자율 모서리 매달리기** | X | X | – | **자격 없음** |
| **레벨업** | X | X | O | **자격 없음** |
| **말풍선 발화** | X | X | – | **자격 없음** |
| **오류 / 예외 상태** | X | X | O | **자격 없음** |
| 발판 소실 매달리기(사용자가 창을 닫음) | O | **X** | – | **자격 없음** |
| 설정창 [미리듣기] | O | O | O | **자격 있음** — 마스터 OFF에서도 나는 유일한 예외 |

**9 / 16 통과 (56.2%).**

몇 건은 판정 사유를 따로 적을 값어치가 있다.

- **자율 3종(착지·파쿠르·매달리기)** — R1에서는 "티어 C, 별도 스위치, 기본 OFF"로 살려 뒀다.
  **R2에서 죽인다.** 리더의 기준을 끝까지 밀면 그게 결론이다. 이 앱은 이미
  **눈으로 보는 자율 구경거리조차 확률 10종을 전부 0으로 내렸다**(`StickConfig.cs:952`).
  귀가 눈보다 관대할 이유가 없다.
- **레벨업** — P1 탈락(패시브 XP가 10초마다 자동으로 쌓인다) + P2 탈락(진행도가 화면에 없다,
  `CharacterProgressionDirector.cs:170`의 `Debug.Log` 한 줄뿐).
  ★ **자격 시험과 접근성 규칙이 서로 독립적으로 같은 답을 냈다** — R1은 "시각 신호가 없어서 보류"였고,
  R2는 "사용자가 한 일이 아니라서 탈락"이다. **두 축이 교차 검증된 것이므로 신뢰도가 높다.**
  해제 조건: ux-designer가 **진행도를 상시 표시**하면 P2가 통과할 수 있다(레벨업이 예상 가능해진다).
  완료 시각 신호만 추가하는 것으로는 **P1이 여전히 막는다.**
- **말풍선** — `design-narrative`가 방금 발화 빈도를 **24초 → 244초(10.3배)** 로 낮췄다.
  거기에 소리를 붙이면 **하루 354번 타이핑 소리가 나는 앱**이 되고, 그 라운드의 성과를 통째로 되돌린다.
- **오류** — 앱이 **자기 문제로** 사용자에게 말을 건다. 그리고 오류음은
  **OS 알림음으로 오인되는 1순위**다. 오류는 `SettingsWindow.cs:27`의 관례대로 **회색 + 사유**로 표시한다.
- **발판 소실 매달리기** — 원인은 사용자(창을 닫았다)지만 **예상할 수 없다.**
  소리가 나면 *"내가 창을 닫았더니 앱이 반응했다"*로 읽혀 **원칙 3(유저 자산 불변)에 대한 오해**를 만든다.
  P1은 통과하는데 P2가 막는 유일한 항목이고, **P2를 쓰는 이유의 실제 사례**다.

### 1-4. 자격이 있는데도 만들지 않는 것 — `FocusCancelled`

집중 세션 중도 취소는 P1·P2를 통과한다. **그래도 만들지 않는다.**
사용자를 나무라는 소리를 만들지 않는다. `StickConfig`의 `pomodoroCancelPoseHoldSeconds` 툴팁이
취소를 **"패널티 없는 톤"**으로 이미 못박았고, ECONOMY_SPEC 4-2도 취소에 동전을 지급한다
(분당 1.0). **소리만 혼자 다른 톤을 내면 안 된다.**

### 1-5. 그 결과 — 카탈로그 18키 → 14키

| 삭제된 키 | 사유 |
|---|---|
| `sfx.land.ambient` | P1 탈락 — 자율 |
| `sfx.parkour.climb` | P1 탈락 — 자율 |
| `sfx.ledge.hang` | P1 탈락 — 자율 |
| `sfx.progress.levelup` | P1·P2 탈락 |

★ **남은 14키는 전부 사용자 조작이 원인이다.** 여기서 따라 나오는 결과가 이 설계의 핵심이다:

> **"팩을 사면 시끄러워진다"가 원리적으로 성립하지 않는다.**
> 팩이 교체할 수 있는 키가 **전부 사용자 조작을 전제**하기 때문이다.

★ **대가(정직하게)**: R1에서 6팩이 **가장 쓰고 싶어 하던 키**(`land.ambient`/`parkour`/`ledge`)가
사라졌다. §3에서 팩별 6키를 **전부 다시 짰다.**

## 2. 기본값과 첫 실행

### 2-1. 기본은 **꺼짐(OFF)** — 바뀌지 않는다

`SILENCE_POLICY.md` §1의 논거 3건이 그대로 유효하고, **오디오가 확정되면서 하나가 더 붙는다.**

| 논거 | 요지 |
|---|---|
| ① **소리는 되돌릴 수 없는 출력이다** | 클릭 관통·자동 숨김의 오판은 회수 가능하다. *"회의실 전원이 그 소리를 들었다"*는 회수 불가 |
| ② **이 앱은 이미 같은 판단을 했다** | 눈으로 보는 자율 구경거리 확률 10종이 전부 0 |
| ③ **기본 ON은 전원에게 청구서를 보낸다** | 아래 ④ |
| ④ ★ **R2 신규 — 자동 서스펜드가 출하 빌드에 없다** | `m_EnableOutputSuspension`을 Unity 공식 소스가 **"(editor only)"**로 라벨한다. 즉 플레이어에서는 무음이 계속돼도 장치가 안 닫힌다 |

★ **첫 실행에 소리는 나지 않는다.** 온보딩에서 **묻지도 않는다.**
처음 쓰는 사람에게 배울 것이 이미 많고, "소리 켤까요?" 팝업은 **아직 신뢰가 없는 앱이 하는 요구**다.

### 2-2. 볼륨 조절 — 필요하다. 자리는 이미 정해져 있다

`SettingsWindow.cs:177-228` 실측: 탭은 `일반 / 캐릭터 / 이벤트 / 접근성·성능 / 데이터` 5개.

| 항목 | 탭 | 근거 |
|---|---|---|
| 마스터 on/off · 볼륨 슬라이더 · 야간 시간대 · **[미리듣기]** | **[접근성 · 성능]** | 탭 문구가 *"내 눈과 내 컴퓨터에 맞추기"*. 소리의 진짜 비용(오디오 장치 상주)은 **컴퓨터에 대한 것**이다 |
| **사운드 테마**(팩 소유 시 하나 선택) | **[이벤트]** | 탭 문구가 *"이 캐릭터가 알아서 하는 일의 범위"*. 팩 콘텐츠의 자리 |
| — | **[일반] 아님** | `SettingsWindow.cs:62` 실측: *"[일반] 탭은 앞으로도 항상 넘친다"*(112 pt 초과) |

★ **R1에서 [이벤트] 탭에 두려던 "티어 C/M 토글 2개는 사라졌다"** — §1-5에서 티어 C/M이 통째로 죽었기 때문이다.
**설정 항목이 2개 줄었다.** 그 자리를 사운드 테마 하나가 대신 쓴다.

볼륨은 R1 §5 그대로: **0~100, 기본 40**, `(s/100)^(5/3)` 곡선(슬라이더 절반 = 체감 절반, 검산 0.4988).

### 2-3. ★ 음소거 상태의 시각 대체 — **필요 없다. 이미 그 반대다.**

이 질문은 순서가 거꾸로다. **화면이 정본이고 소리는 그 위에 얹는 장식이다.**
기본값이 OFF이므로 **사용자의 100%가 소리 없이 앱을 쓰고 있고, 그것이 정상 상태다.**
"음소거일 때 시각 대체를 넣는다"가 아니라 **"시각이 먼저 있어야 소리를 붙일 수 있다."**

강제 방법: 카탈로그의 각 키는 `visualCounterpart`를 **반드시** 갖는다. 비면 출하 금지.
회귀 테스트 1건으로 잠근다(**빈 목록을 기대값으로 명시** — TEAM.md 거짓통과 #5 회피).

그리고 이 규칙이 R2에서 실제로 하나를 막았다: **레벨업.** §1-3 참조.

### 2-4. 침묵의 사유를 반드시 보여준다

사유 없는 침묵은 **반드시 "소리가 안 나요" 버그로 신고된다.**
설정창 소리 행은 지금 상태와 사유를 한 줄로 보인다:

```
지금 소리: 꺼짐 — 야간(23:00~07:00)
지금 소리: 꺼짐 — 전체화면 게임 감지
지금 소리: 켜짐
```

## 3. ★ DLC 팩별 사운드 — 되돌릴 수 없는 부분

### 3-1. 덮어쓰는가, 더하는가 → **덮어쓴다. 1 트리거 키 = 최대 1 클립.**

6팩 전량 소유 시 키 충돌 실측(§4 계산):

| 키 | 교체를 원하는 팩 수 |
|---|---:|
| `sfx.land.throw` | **6** |
| `sfx.equip.wear` | 5 |
| `sfx.focus.start` / `focus.complete` / `equip.remove` / `archery.release` | 각 3 |
| 나머지 6키 | 각 2 |

**더하기로 갔을 때 무슨 일이 나는가 — 숫자로:**

```
같은 키에 6클립 동시 재생 -> 이론 합성 이득 +15.56 dB
마스터 기본(-13.26 dB) 위 출력 피크 : -14.26 dBFS  ->  +1.30 dBFS
OS 알림음(-6 dBFS 가정) 대비 여유    :  +8.26 dB   ->  -7.30 dB   ★ 역전
동시 발성 상한 3                    :  6 > 3      ★ 즉시 초과
```

즉 더하기는 **두 가지를 동시에 깬다**: (a) 볼륨 예산 전체, (b) **"돈을 낼수록 시끄러워지는" 구조**.
후자는 R1 §3-1-3이 *"팩에 볼륨 필드를 넣지 마라"*로 이미 금지한 것과 **정확히 같은 위반**이며,
더하기는 볼륨 필드 없이도 그것을 달성한다. **협상 불가.**

### 3-2. 여섯 팩을 다 켜면 어떻게 되는가 → **하나만 울린다. 사용자가 고른 하나.**

**채택: 사용자가 설정창 [이벤트] 탭에서 사운드 테마를 정확히 하나 고른다.
기본값은 `기본(팩 없음)`이고, 팩을 사도 소리는 자동으로 바뀌지 않는다.**

| 기각안 | 왜 |
|---|---|
| 로드 순서 / `packVersion` 최신 우선 | **비결정적.** 팩 업데이트가 사용자가 고른 적 없는 소리 변경을 일으킨다 |
| 착용 중인 4슬롯 다수결 | 4슬롯이라 **2:2 동률이 흔하고**, 모자 하나 바꾸면 소리 6개가 조용히 전부 바뀐다 |
| 매니페스트에 우선순위 `int` | 팩끼리 숫자 경쟁이 시작된다. **볼륨 필드와 같은 종류의 누수** |

> **팩을 사도 소리가 자동으로 안 바뀌는 게 손해 아닌가?** 아니다.
> 소리는 **선택되지 않은 채로 바뀌면 안 되는 유일한 출력**이다. 팔레트는 눈이 보고 넘기면 되지만,
> 소리는 사용자가 "왜 소리가 달라졌지?"를 **원인 없이** 겪는다.
> 대신 **테마 선택 UI 옆에 [미리듣기]** 를 둔다 — 사도록 만드는 건 그 버튼이지 자동 적용이 아니다.

### 3-3. ★ 이펙트와 반드시 다르게 구현해야 한다 (구현자 함정)

`ARCHITECTURE.md` 5-3-2 (D)의 `PluginRegistry`는 `(stateId, trigger) → 이펙트 **목록**`이다 — **더하기**.
사운드는 `triggerKey → 클립 **하나**`다 — **덮어쓰기**.

**같은 레지스트리 헬퍼를 재사용하면 사운드가 조용히 더하기가 된다.**
조회 함수 시그니처부터 다르게 만든다:

```
IReadOnlyList<EffectPluginSO> ResolveEffects(StickmanStateId, EffectTrigger)   // 목록
string                        ResolveSoundAssetKey(string triggerKey)          // 단수 — 없으면 null
```

`ResolveSoundAssetKey`가 **리스트를 반환하지 않는 것 자체가 계약**이다.

```
StickmanAgent.Tick():  if (_isSuspended) return;      // StickmanAgent.cs:623 [실측]
```

Tick이 조기 반환하므로 **상태 전이가 아예 일어나지 않는다** → 상태 파생 소리는 **발생 자체가 불가능**하다.

다만 **상태 밖 경로**(설정창 버튼 / 구매 / 미리듣기)는 별도 게이트가 필요하다.

> ★ **R3 정정 — 여기서 고른 값이 틀렸다.**
> 초판은 **M8 = `StickmanAgent.IsSuspended`**로 쓰고 *"사운드가 두 축을 따로 볼 이유가 없다"*고 적었다.
> **축은 둘이 아니라 셋이다.** `IsSuspended = _fullscreenAutoHide || _userHidden`(`StickmanAgent.cs:1250`,
> 초판이 적은 `:1152`는 줄이 밀린 값이다)이고, **축 3 `_fullscreenPanelRetreat`(등급 1)가 빠져 있다.**
> 등급 1에서 `IsSuspended`는 **false**이므로 **발표·화상회의 중에 소리가 난다.**
> 코드에 경고가 이미 있었다(`StickmanAgent.cs:140-143`):
> *"화면 표면을 걷을지를 묻는 소비자는 이 값이 아니라 `ArePanelsSuppressed`를 읽어야 한다."*
> **소리는 표면보다 더 새 나가는 출력이다** — 표면이 물러나는 자리에서 소리가 남을 이유가 없다.
>
> → **M8 = `StickmanAgent.ArePanelsSuppressed`** (= 축 1·2·3 전부). 진리표 8행 중 **1행(12.5%)**이 갈리고
> 그 1행이 정확히 발표/화상회의다. 현행 무음이 소리로 바뀌는 행은 **0행**(약화 없음).

★ **F4 추가 실측**: `FocusWatchDirector.Update()`는 `if (_player.IsSuspended) return;`이라
**등급 1에서는 집중 타이머가 계속 흐른다.** 즉 발표 중에 25분이 만료되고 `CompleteSession()`이 실제로 불린다.
등급 1을 게이트에 넣지 않으면 **이 경로가 그대로 소리로 나간다.**

★ **F1~F3 실측 — `focus.complete`를 상태 전이에 묶으면 안 된다:**
```
CompleteSession() { IsSessionActive = false; TryTriggerPoseState(FocusComplete); }
TryTriggerPoseState: current != Idle && current != Walk        -> 조용히 스킵
                     SpectacleEventLock.IsActive               -> 조용히 스킵
```
**포즈 전이는 best-effort고, 세션 완료(동전 지급)는 무조건 일어난다.** 둘은 같은 사건이 아니다.
소리를 `StickmanStateId.FocusComplete` **전이**에 걸면 캐릭터가 마침 래그돌·파쿠르 중이거나
다른 구경거리가 락을 쥔 순간 **동전은 들어왔는데 소리는 안 나는** 조용한 실패가 된다.
→ **`sfx.focus.complete`는 `CompleteSession()`의 세션 완료 사실에 건다.** 포즈 전이에 걸지 않는다.
(원칙 1과 충돌하지 않는다 — *세션 완료*가 확정된 상태 전이이고, *포즈*는 그 위의 연출일 뿐이다.)

예외 1건: **[미리듣기]** 는 숨김 중에도 난다 — 설정창을 열어 그 버튼을 누른 것 자체가 명시적 동의다.
(숨김 중에 설정창이 열려 있을 수 있는지는 `ux-designer` 확인 사항. 열 수 없다면 이 예외는 사문이 된다.)

### 4-5. 전역 안전망 — 버그가 소음 사고가 되지 않게

티어 A에는 예산을 두지 않는다(사용자가 누른 것에 "너무 자주 눌렀다"고 막으면 고장으로 읽힌다).
대신 **runaway 방어용 전역 상한**을 둔다.

```
활쏘기 1시퀀스 최소 = 2.96 초  (StickConfig 실측 합:
  targetIntro .55 + draw .42 + aimHold .30 + arrowFlight .62 + recoil .18 + recover .34 + outro .55)

이론 최대   60.8 소리/분  (접근 이동 0초 — 실현 불가)
현실 최대   22.6 소리/분  (접근 5초 [가정])
원형 B 피크  3.0 소리/분

→ 전역 안전망 = 60초 슬라이딩 윈도우 40회
   현실 최대의 1.77배 / 원형 B 피크의 13.3배
```

★ **이 안전망이 걸리면 그것은 "조용해졌다"가 아니라 "버그다".**
걸린 순간 **경고 로그**를 남긴다. 조용히 흡수하면 그 버그는 영원히 안 보인다.

## 6. 재발행 비용 — 지금 굳는 것 4건뿐

`game-architect`: *"팩은 6개라 재발행 비용이 세이브의 6배다."*

| 스키마 요소 | 재발행? | 이유 |
|---|:--:|---|
| **트리거 키 문자열 집합** | **예** | 팩이 문자열로 참조한다. **이름 변경·삭제 = 6팩 전부 깨짐** |
| **`assetKey` vs `AudioClip` 직접참조** | **예** | 직접참조면 미소유 팩도 매니페스트와 함께 로드된다 |
| **클립 원본 포맷**(모노/48k/16bit/WAV) | **예** | 재수록은 원본 재작업 = 6팩 전부 |
| **`soundSchemaVersion` 필드 존재** | **예** | 없으면 키 집합을 **영원히 버전할 수 없다** |
| 팩당 키 상한 6 | 아니오 | 늘리는 건 하위 호환 |
| 키 **추가** | 아니오 | 구팩은 그 키를 안 덮을 뿐 — 기본 클립이 난다 |
| 음색·믹싱(클립 내용) | 아니오 | 같은 키에 새 파일 = 팩 업데이트 1건 |
| 티어/예산/볼륨/묵음 | 아니오 | ★ **애초에 팩 스키마에 없다**(앱 소유) |

**즉 "지금 안 정하면 6팩 재발행"인 것은 4건뿐이고, 이 문서가 넷 다 정했다.**

★ **키 이름 규칙(불변)**: `sfx.<도메인>.<사건>`. 소문자·점 구분.
**키는 추가만 가능하고, 이름 변경과 삭제는 금지다.** 죽은 키는 카탈로그에
`deprecated: true`로 남겨 두고 재사용하지 않는다(팩이 그 이름을 계속 참조할 수 있으므로).

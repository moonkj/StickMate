# SPEC — 언어 인식 가독예산 게이트 (`DialogueBudget.ReadingSeconds`)

담당 `design-narrative` 작성 / **구현은 `coder`** (리더 배정 대기)
독립 문서다. 이 파일 하나만 읽고 착수할 수 있게 썼다.
출처: `design/narrative/2026-09-02_R2_발화빈도_풀24_영어게이트.md` §5·§7-1을 구현 사양으로 확정한 것.
검산: `design/narrative/verify/{en_budget,gate_charclass}.py` (`.out.txt`가 실행 결과)

> **한 줄**: `PerGlyphSeconds = 0.075f`는 이름과 달리 **0.075초/음절**이고,
> `text.Length`가 그것을 **0.075초/글자**로 읽는다. **한글에서만 글자 = 음절이라 안 들켰다.**

---

## 0. 왜 이것이 우선순위 최상인가

이 저장소의 로컬라이제이션은 **이 함수 하나에서 막힌다.** 영어 대사를 아무리 잘 써도
게이트가 침묵시킨다. 그리고 **증상이 로그 한 줄뿐**이다 —
`AmbientChatter.cs:186`의 `[말풍선] 발화 보류` 로그는 정상 동작에서도 나오므로,
"영어판에서 캐릭터가 조용하다"는 **아무도 버그로 신고하지 않는 형태**로 출하된다.

## 1. 지금 코드 (읽기 전용 인용)

`Assets/_Project/Scripts/Dialogue/DialogueKind.cs`

```csharp
private const float BaseSeconds     = 0.28f;   // 글자수와 무관한 기본 인지 시간
private const float PerGlyphSeconds = 0.075f;  // "한 글자당 추가 가독 시간"
public  const float MinSeconds      = 0.62f;
public  const float MaxSeconds      = 2.20f;

public static float ReadingSeconds(string text)
{
    int glyphs = string.IsNullOrEmpty(text) ? 0 : text.Length;
    return Mathf.Clamp(BaseSeconds + glyphs * PerGlyphSeconds, MinSeconds, MaxSeconds);
}
```

주석은 **`BaseSeconds`(눈이 글자 블록을 찾아가는 몫)와 `PerGlyphSeconds`(읽는 몫)를 옳게 구분**해
두었다. **구분은 맞고, 두 번째 항의 단위만 틀렸다.**

## 2. 반증 — 게이트가 "읽는 시간이 더 짧은 쪽"을 침묵시킨다

| 한국어 | 음절 | 글자 | English | 음절 | 글자 | 게이트 판정 |
|---|--:|--:|---|--:|--:|---|
| `헉... 높다` | **3** | 7 | `Whoa, that's high` | **3** | 17 | 영어만 **침묵** |
| `어우... 꽤 깊네` | **5** | 10 | `Whoa... that's deep` | **3** | 19 | 영어만 **침묵** |

**둘째 행을 보라. 영어 쪽이 음절이 더 적다 — 읽는 데 시간이 더 적게 든다.**
그런데 글자수가 1.9배라서 침묵한다. **문안 문제가 아니라 단위 오류다.**

---

## 3. 계수 `w`의 유도 — 고른 게 아니라 풀었다

**불변식**: *같은 발화는 같은 가독예산을 청구받는다.*
(언어 간 정보 전달률이 거의 일정하다는 방향 — Coupé et al. 2019, *Science Advances*)

```
0.28 + w·G_en  =  0.28 + 0.075·G_kr        →   w_i = 0.075 · G_kr / G_en
```

실재 대사 **17줄** + 각각의 **영어 재창작**(번역 아님)으로 풀었다
(`verify/en_budget.py`, 말뭉치는 그 파일의 `PAIRS`에 있다):

| 추정치 | 값 |
|---|---:|
| 줄별 `w_i`의 중앙값 | 0.0500 |
| 줄별 `w_i`의 평균 | 0.0494 |
| **말뭉치 전체 글자수 비율** (한글 112자 / 영어 178자 = 0.629) | **0.0472** |

**채택 `w = 0.0472`초/라틴글자.** 전체 비율을 쓰는 이유: 불변식이 요구하는 것이
*"풀 전체가 두 언어에서 같은 예산을 청구받는다"*이므로, 길이 가중이 들어간 이 추정치가
**그 불변식 자체**다. 중앙값과 0.6% 차이라 어느 쪽을 써도 결과가 같다.

> ★ **임의로 더 내리지 마라.** "안전하게" 낮추면 침묵은 줄지만 **글자가 읽히기 전에 사라진다** —
> 그건 규칙 8이 없애려던 결함(`0.08초 번쩍이고 사라지는 글자`) 그 자체다.
> **이 저장소에서 안전한 실패는 침묵이지 조기 소멸이 아니다.**

## 4. 요구 구현

```
ReadingSeconds(text):
  ① text에 <CJK 문자>가 하나라도 있으면
       cost = PerGlyphSeconds(0.075) × text.Length          ← 현행과 문자 그대로 동일
  ② 그 밖(라틴 전용)이면
       cost = PerLatinGlyphSeconds(0.0472) × text.Length
  return Mathf.Clamp(BaseSeconds + cost, MinSeconds, MaxSeconds)   ← 나머지 무변경
```

### 4-1. ★ `<CJK 문자>`의 정의 — 코드포인트로 못 박는다

| 블록 | 범위 | 넣는가 | 이유 |
|---|---|---|---|
| 한글 음절 | `U+AC00..U+D7A3` | **넣는다** | 지금 대사 116자 전부가 여기다 |
| **한글 자모(호환)** | `U+3130..U+318F` | **넣는다** | ★ `ㅋㅋㅋ` `ㅎㅎ` — **가장 흔한 누락**(§4-2) |
| 한글 자모(조합용) | `U+1100..U+11FF` | 넣는다 | 위와 같은 이유. 정규화 안 된 입력 |
| 한글 자모(확장) | `U+A960..U+A97F`, `U+D7B0..U+D7FF` | 넣는다 | 완전성 |
| CJK 통합한자 | `U+4E00..U+9FFF` | 넣는다 | 중국어/일본어 이식 시 같은 함정 |
| 가나 | `U+3040..U+30FF` | 넣는다 | 위와 같음 |

### 4-2. ★ 가장 흔한 누락 — `ㅋㅋㅋ`

한글 음절 범위(`U+AC00..U+D7A3`)만 보면 **`ㅋㅋㅋ`(U+314B)는 라틴 분기로 떨어진다.**
지금 말뭉치에는 자모가 0자라 **테스트가 초록인 채로 이 구멍이 통과한다.**
길이가 짧을 때는 둘 다 하한 `MinSeconds`에 걸려 차이가 안 보이고, 길어지면 갈라진다:

```
"ㅋㅋㅋㅋㅋㅋㅋㅋㅋㅋㅋㅋ" (12자)  CJK분기 1.180초  vs  라틴분기 0.846초  — 0.334초 차이
```

(`verify/gate_charclass.out.txt`)

### 4-3. 혼합 문자열은 **①**로 간다

`"Wi-Fi 끊겼네"`(9자)는 한글이 있으므로 CJK 분기 → 0.955초.
라틴 분기였다면 0.705초다. **더 비싸게 청구하는 쪽을 고른다** —
과다 청구의 결과는 **침묵**이고, **침묵은 거짓말이 아니다.**

### 4-4. 상수의 자리

`PerLatinGlyphSeconds = 0.0472f`를 `PerGlyphSeconds` **바로 옆**에 둔다.
주석에 유도 근거 한 줄 + `design/narrative/verify/en_budget.out.txt` 경로를 남긴다.
**하드코딩 금지 대상이 아니라 튜닝 상수다** — 다만 테스트에서 이 값을 숫자로 베끼면 안 된다(§6 T6).

### 4-5. 형태는 안 바뀐다

`RequiredDwellSeconds(text, fadeIn)` / `IsEligible(line, plannedDwell, fadeIn)`의 **시그니처와
의미는 그대로**다. 사용자 노출 배율을 게이트에 곱하지 않는다는 이미 비준된 성질
(`DialogueKind.cs` 문서, `DialogueVisibleScaleContractTests`가 리플렉션으로 잠그고 있다)에
**아무 영향이 없다.**

## 5. ★ 한국어 결과 **비트 단위 불변** — 이 변경의 합격 조건

분기 ①이 현행 식과 **문자 그대로 동일**해야 다음이 전부 보존된다:

| 보존 대상 | 어디 |
|---|---|
| 실재 대사 33줄의 게이트 거동 | `AmbientChatter` / `States/*` |
| 주석에 구워진 값 `0.680 / 0.715 / 0.865` | `ParkourClimbState.cs` |
| 노출 상한 `MaxVisibleSecondsFor` | `DialogueBubbleRenderer.cs:1221` |
| 최소 노출 `MinVisibleSecondsFor` | `DialogueBubbleRenderer.cs:1170` |
| ★ **정보창 프레즌스 줄의 hold 시간** | `CharacterInfoWindow.cs:845` |

> ★ **다섯 번째를 놓치지 마라.** `ReadingSeconds`는 **대사 전용이 아니다.**
> `CharacterInfoWindow.WritePresence`가 `"지금 · 걷는 중"`의 유지 시간을 이 함수로 잰다.
> 즉 이 변경은 **대사 시스템 밖으로 새어 나간다.** 한국어 불변이 지켜지면 그 표면은
> 한 프레임도 안 바뀌지만, **영어 UI가 붙는 날 그 hold도 함께 짧아진다**(그리고 그것이 옳다).
> 이 사실을 `ReadingSeconds`의 XML 주석에 적어 두어라 — 다음 사람이 같은 발견을 다시 하지 않게.

**요구**: 현행 실재 대사 전량에 대해 개정 전/후 `ReadingSeconds`가 **완전히 같은 float**임을
테스트로 잠근다. **하나라도 다르면 이 변경은 무효다.**

## 10. 미확인 (거짓 통과 방지)

1. **`w = 0.0472`는 말뭉치 17쌍에서 유도한 값이지 사용자 실측이 아니다.** 영어 원어민이
   실제로 그 시간에 읽는지는 재지 않았다. 재려면 사용자 테스트가 필요하다 — **미확인.**
2. **영어 서체의 실제 자폭을 재지 않았다.** 이 사양은 **시간**만 다루고 **폭**은 다루지 않는다.
   말풍선 폭이 넘치는지는 `DialogueBubbleRenderer` 소관이고 **이 문서 범위 밖**이다.
3. **Unity의 `string.Length`는 UTF-16 코드유닛 수**다. BMP 밖 문자(이모지)는 서로게이트 쌍이라
   1글자가 2로 세어진다. 지금 말뭉치에 이모지는 **0자**지만, 들어오면 **과다 청구 → 침묵**이다.
   안전한 방향이라 이번 사양에서는 다루지 않는다 — **알고 남겨 둔다.**

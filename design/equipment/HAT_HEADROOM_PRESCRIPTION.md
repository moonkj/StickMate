## 1. 진단 — 왜 "ㅁ자 창"이 생기는가 (기하)

### 1-1. 챙의 부피를 세로로 만들면 그 부피가 곧 머리를 지운다

지금 챙·단은 전부 **머리 원을 가로지르는 두꺼운 색 막대**다. 실측(현행 좌표):

| 도형 | 머리 원반 위 면적 | 챙 전체 대비 |
|---|---|---|
| `BeanieCuff` | **1.055 R²** | 94% |
| `FedoraBrim` | **0.902 R²** | 68% |
| `StrawBrim` | **0.790 R²** | 60% |
| `HatBrim`(야구) | **0.643 R²** | 72% |

머리 원반 전체가 π = 3.14 R²다. 즉 챙 하나가 머리의 **20~34%를 색으로 덮는다.**
사용자가 "ㅁ자 창 때문에"라고 지목한 것이 정확히 이 막대다.

### 1-2. 그런데 챙은 **옆에서 보면 얇다** — 그것이 챙의 실제 기하다

챙은 원반이다. 옆에서 보면
* **얼굴 앞을 지나는 구간**(머리 원 안)은 원반을 **모서리로** 보는 자리라 판 두께만큼만 보인다.
* **앞뒤 끝**(머리 원 밖)은 원반이 시선 쪽으로 기울어 있어 **더 두껍게 보이고, 처짐도 여기서 보인다.**

현행 좌표는 이 관계가 **뒤집혀** 있다 — 머리 위에서 0.43~0.58 R로 가장 두껍고, 머리 밖에서 얇아진다.
**처방은 그 순서를 되돌리는 것이다.** 취향이 아니라 원반의 투영이다.

### 1-3. 두께 예산 — 배율 0.60에서 무엇이 가능한가

배율 0.60에서 머리 지름은 **4.65획**(W = 0.4298 R)이다. `headroom.py`의 하한/목표를 잉크 밑단으로 옮기면

```
남는 머리 >= 1.00획  ->  잉크 밑단 >= -1 + 0.42983          = -0.5702 R   (하한)
남는 머리 >= 1.20획  ->  잉크 밑단 >= -1 + 1.20 x 0.42983   = -0.4842 R   (목표)
모자의 머리 위 색 밴드 >= 2획(13-2)  ->  잉크 밑단 <= +0.14 R
                    => 잉크 밑단의 가용 창 = [-0.484, +0.14] R
```

처방의 잉크 밑단은 **−0.352 ~ −0.475 R**로 이 창 안에 전부 들어간다.
그리고 잉크 밑단은 `(채움 다각형 밑변) − W/2`이므로, 챙이 x=0에서 가질 수 있는 채움 두께의 상한이 곧
`커버선 − (−0.269) ≈ 0.35 R` 이다. **처방의 머리 위 챙 두께 0.33~0.34 R(야구는 뒤로 수렴하는 자리라 0.18 R)은 이 부등식이 정해 준 값이다.**

## 2. ★ 이 라운드의 진짜 제약 — 규칙 1-C(색면 조건)

오늘 새로 들어온 `Tests/EditMode/AccessoryFillAreaRuleTests`가 **채운 도형마다**

```
ρ_max(최대 내접원 반경) >= W_out = FillOutlineBudgetInHeadRadii(s) = 0.21818 R   (배율 0.591 이상 상수)
```

를 하드 게이트로 건다(면제 대장 4줄, 모자는 한 줄도 없다). 즉 **채움은 어딘가 한 곳에서 두께 0.436 R 이상**이어야 한다.

이것과 1-3의 "머리 위에서는 0.35 R 이하"가 **동시에 성립하려면 두꺼운 자리가 머리 원 밖이어야 한다.**
1-2의 조형 원리와 1-C의 산술이 **같은 답**을 가리킨다 — 그래서 이 처방이 성립한다.

### ★ 털모자만은 그 답이 안 나온다 — 그래서 단을 **선으로** 바꿨다

접힌 단을 밑단 −0.26 R까지 올리면 단의 두께는 커버선(−0.06)과의 차 **0.20 R**뿐이다.
채움으로는 ρ_max ≈ 0.10 R로 **1-C를 절대 통과할 수 없다.** 단을 두껍게 하려면 밑단을 −0.50 R까지
내려야 하고 그러면 남는 머리가 0.66획으로 무너진다. **두 요구가 배타적이다.**

풀이: **관과 단을 한 채움으로 합치고, 접힌 자리는 그늘색(`Shade`) 낱선 하나로 긋는다.**
`docs/EQUIPMENT_SHAPE_SPEC.md` 3절 원칙 7 그대로다 — *"실루엣 = 채운 덩어리 / 디테일 = 선 1개"*.
이 배율에서 접힌 단은 덩어리가 아니라 **선**이다. 선은 1-C의 대상이 아니다(낱선 20개는 2.00pt 그대로).

* 실루엣은 **한 점도 안 변한다**(합집합이 같다) → 쌍별 실루엣 차 무영향
* 겹치는 채움이 사라져 `ApplyAlpha` 페이드 중 이음매 위험이 0이 된다(스펙 13-6이 풀이 1을 기각한 사유)
* 낱선의 두 점은 관의 허리 두 점을 **그대로 받는다**(좌표를 새로 적지 않는다 — 규칙 4-a)

## 3. 처방 — `AccessoryShapeBuilder.cs` 정확한 상수명 = 새 값

> 좌표계는 이 문서 전체가 **머리 중심 원점 · R 배수**다.
> 프로덕션 변환: `프로덕션_점 = rig.F(x * r, hc + y * r)`, `hc = rig.HeadCenterY`, `r = rig.HeadRadius`.
> **왕관·베레모는 한 글자도 건드리지 않는다** — 이미 하한도 목표도 통과한다(4절 표).

### 3-2. 야구모자 — `HatBrim(in Rig rig)` (현재 ~903행)

7점 유지. **점 4개만 움직인다.**

```csharp

{

    HatCrownFrontFoot(rig),                                       // 무변경 (+0.60, +0.04)

    rig.F(r * 0.62f, hc - r * 0.26f),                             // ← (0.40, -0.44)  ★ 머리 위 구간을 얇게
```

## 7. ★ 발견 — `headroom.py`가 M6 이전 모델이다 (리더 판단 필요, 이 처방과 별개)

`headroom.py.stroke_in_R()`은 **낱선 하한 2.00pt**로 획을 계산하고 그것으로 모자 잉크의 W/2 팽창을 준다.

| 배율 | 모자 | 현행 실제 잉크 밑단 | 남는 머리 | **처방 실제 잉크 밑단** | **남는 머리** |

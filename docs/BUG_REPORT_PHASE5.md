## 결론 요약

**Blocker 0건, Major 2건(BUG-P5-M1, BUG-P5-M2, 모두 신규), Minor 2건(관찰/확인요청).**

- **점검 1(Kinematic 채택 근거)**: Coder가 "Play 모드 씬이 없어 실측 못함"이라 자평한 것과 달리, 이 판단은 실측 없이도 Unity 공식 문서 기준으로 정적 검증 가능하며 **검증 결과 정확하다.** `Rigidbody2D.simulated=false`는 해당 Collider2D를 Physics2D 쿼리(레이캐스트 포함) 대상에서 완전히 제외시키는 것이 Unity의 문서화된 동작이고, `Interaction/StickmanClickHitbox.cs` 자신의 문서 주석도 "OnMouseDown은 엔진이 Camera 기준 Physics2D 히트테스트를 매 프레임 자체 수행"이라고 명시한다 — 즉 `simulated=false`를 썼다면 은신 중 클릭 감지가 100% 죽었을 것이라는 Coder의 우려는 문서상 사실이며, `Kinematic`(콜라이더는 여전히 쿼리 대상)을 택한 것은 정확한 대안이다. 다른 Rigidbody2D와의 충돌 무시(Kinematic 특성)로 인한 부작용은 20/24절의 상호배제 세트(가출 중 다른 스펙터클 금지)가 이미 충돌 유발 경로 자체를 차단하므로 실질적 위험은 낮다고 판단했다 — **버그 아님, 근거 확인 완료.**
- **점검 2(자동 복귀 타이머와 Suspended)**: `RunawayState`가 `StickmanAgent.Suspend()`의 강제 Idle 목록에 없어(코드 확인), Runaway 중 전체화면이 감지되면 `_isSuspended=true`가 되고 `Update()`가 `_machine.Tick(dt)` 자체를 건너뛴다 — Coder 설명대로 자동 복귀 타이머(`_totalHiddenTimer`)도 함께 정지했다가 재개되며, "Tick이 다른 이유로 멈춰 영원히 숨어있는" 회귀는 없음을 확인했다(Tick은 Suspended가 아닌 한 항상 호출됨). **다만 이 조사 과정에서 정반대 방향의 실제 버그(BUG-P5-M1, 아래 상세)를 발견했다** — "너무 오래 숨어있는" 문제가 아니라 "Suspend/Resume 왕복 한 번으로 아직 발견되지 않았는데 강제로 보여지는" 문제다.
- **점검 3(긴급정지 다중 구독자 간섭)**: `GlobalEmergencyStopRequested`를 구독하는 9개 Interaction Director를 전수 확인한 결과, `RunawayDirector`를 포함한 8개는 `SpectacleEventLock.CurrentOwner==this`(또는 `CurrentStateId==해당 상태`) 가드로 자기 소관이 아니면 즉시 no-op — 가출 중이 아닐 때 로데오만 진행 중인 상태에서 긴급정지를 눌러도 `RunawayDirector.OnEmergencyStop()`은 `CurrentStateId != Runaway`라 아무 일도 하지 않음을 확인했다(간섭 없음). 예외 1건(`StressGaugeDirector`)은 의도적으로 무조건 실행(긴급정지 "반복 사용 빈도" 자체를 추적해야 하므로 모든 사용을 관찰해야 함) — 설계 의도와 일치. 예외 2건째(`FocusWatchDirector`)는 소유권 가드 없이 항상 `IsSessionActive=false`를 실행 — 실제 부작용 있음(Minor 2, 아래 상세).

- **점검 6(TodoPostItWidget 독립성)**: `grep`으로 `SpectacleEventLock`/`ILocalClickCaptureService`/`StickmanClickHitbox` 실참조 0건(전부 문서 주석 안에서만 텍스트로 등장) 재확인. `EnsureEventSystem()`이 `EventSystem.current != null`이면 생성을 스킵함을 확인했고, 프로젝트 전체에서 `EventSystem` GameObject를 만드는 코드는 이 한 곳뿐임을 grep으로 확인(중복 생성 경로 없음 — 여러 컴포넌트가 같은 프레임 `Awake()`에서 동시에 처음 생성을 시도하는 것은 Unity 자체의 일반적 초기화 순서 한계이지 이 코드 특유의 결함은 아님). **버그 아님, 근거 확인 완료.**

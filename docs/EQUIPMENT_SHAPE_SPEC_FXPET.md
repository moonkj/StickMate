## 1. 왜 이 12종만 "조잡함"이 안 고쳐졌는가 — 구조적 원인 3건

30종과 12종을 가르는 것은 취향이 아니라 **코드 구조 세 가지**다. 좌표를 아무리 고쳐도
이 셋이 남아 있으면 12종은 계속 뒤처진다.

### 1-1. 채움 경로가 **없다**

`Interaction/CharacterAccessoryRenderer.cs`에는 `MeshRenderer` 기반 채움 경로가 있다
(`AddFill` / `BuildFillMesh`, 윤곽선 바로 아래 `SortingOrder − 1`).
`CharacterFxRenderer.cs`와 `CharacterPetRenderer.cs`에는 **`Mesh`라는 낱말이 한 번도 나오지 않는다.**

39절이 반증한 원칙("채움은 가림용만")의 결론은 **"이 엔진에서 굵은 덩어리를 만드는 유일한 수단이
`filled`다"** 였다. 그 수단이 12종에는 물리적으로 없다. **12종이 전부 윤곽선인 것은 디자인 선택이
아니라 렌더러의 부재다.**

### 1-2. FX에는 **보조색이 없다**

`CharacterPetRenderer`는 `ItemCatalog.ResolveWornPalette(...)`로 주색/보조색을 받아
`_primary`/`_secondary`를 쓴다. `CharacterFxRenderer`는 그 호출이 **아예 없고**,
모든 선이 `ResolveInk()`(캐릭터 잉크색) 하나다.

→ FX 5종은 규칙 3-2(보조색 정확히 1개)를 **구조적으로 만족할 수 없다.**
→ 그리고 카탈로그가 FX 카드에 칠하는 색(TintHead/TintEyes 계열)은 **카드에만 존재한다**.
   착용하면 그 색이 사라진다. 이것이 "카드 그림과 실제 착용 모습이 다르다"의 FX판이다.

### 1-3. 카드가 여전히 **손으로 놓은 40×40 SVG**다

`Interaction/AccessoryCardIcon.TryBuild`는 FX/PET에서 **false를 돌려준다**(그 파일의 문서가
"정상 경로"라고 스스로 적어 두었다). 즉 2026-09-01 카드 통합 라운드가 30종에서 닫은
**"한 아이템이 두 벌의 그림을 갖는" 결함이 12종에는 그대로 남아 있다.**

실측 괴리(같은 아이템, 다른 그림):

| 아이템 | 카드가 그리는 것 | 월드가 그리는 것 |
|---|---|---|
| 발자국 | 점 **4개가 대각선으로 이어진 자국열** | 둥근 점 **1개** |
| 작은공 | 원 + **하이라이트 호** + **바닥 그림자 호** | 원 + **중심에서 뻗은 바퀴살** |
| 나뭇잎 | 잎몸 **4점** 사각형 | 잎몸 **6점** 육각형 |
| 반짝임 | 갈래 4 + 대각 눈금 4 = **도형 8개** | 십자 **2획** |

### 2-2. 한 가지 원인이 6건을 만든다 — **각수(角數)를 반지름이 못 낸다**

반지름 r(R 배수)의 정n각형은 한 변이 `2r·sin(π/n)`이다. 이것이 1 획을 넘으려면

```
n ≤ π / asin( W / (2r) )          W = 0.343864 R
```

| 도형 | r | 쓸 수 있는 최대 n | 현행 n | 실측 변 |
|---|---|---|---|---|
| 물방울(최소) | 0.522 | **9** | 12 | 0.79 획 ✗ |
| 작은공 | 0.569 | **10** | 12 | 0.86 획 ✗ |
| 달팽이 껍데기 | 0.680 | **12** | 14 | 0.88 획 ✗ |
| 달팽이 속점 | 0.150 | **4** | 8 | 0.33 획 ✗ |
| 먼지 초승달(큰/작은) | 0.50 / 0.325 | 200°를 **3분할** | 5분할 | 0.71 / 0.46 획 ✗ |

**각수 12·14는 액세서리 쪽에서 그대로 베껴 온 값이다.** 액세서리 원(모자 관·방울)은 반지름이
0.8~1.0 R이라 12각을 낼 수 있었지만, FX/PET의 원은 그보다 작다. **반지름이 각수를 살 수 있는지
아무도 확인하지 않았다.**

### 2-3. ★ 왜 린트가 못 잡았나 — "45도 함정"이 6건을 통째로 숨겼다

`AccessoryStrokeBudgetTests.DescribeRuleOneViolation`은 **"양끝이 모두 꺾임(≥45°)인 변"만** 잰다.
정12각형의 꺾임은 **30°**, 정14각형은 **25.7°**, 5분할 초승달은 **40°** — 전부 문턱 아래다.
그래서 **위 6건은 규칙을 어기면서 린트에 한 줄도 찍히지 않는다.**

이 함정은 이 저장소가 이미 한 번 발견해 문서로 남겼다(`AccessoryShapeBuilder`의 폼폼 문단:

## 3. ★ 새 규칙 — 입자형 아이템(FX)의 정원/보조색은 **카드에 건다**

FX 5종은 "한 알"이 화면에 여러 개 뜨는 **입자**다. 한 알에 도형 2~4개와 보조색 1개를 넣으려면
알 하나가 커져야 하는데, 발자국 실측이 그것이 **불가능**함을 보여 준다:

```
한 발자국을 두 조각(밑창 + 앞꿈치)으로 나누려면
  각 조각 잉크 사각형 ≥ 1.5 W = 0.516 R
  두 조각이 안 붙으려면 중심 간격 ≥ 1.5 W = 0.516 R
  → 전체 길이 ≥ 0.516 × 3 = 1.548 R = 4.50 W = 9.0 pt
  머리 지름이 11.63 pt다. 발자국이 머리 지름의 78%가 된다.
```

그런데 **카드는 이미 무리를 그리고 있다** — 물방울 카드는 방울 3개, 발자국 카드는 자국 4개다.
그것이 옳다: 입자의 정체는 "한 알의 모양"이 아니라 **"여럿이 만드는 무늬"**이기 때문이다.

> **규칙 39-P(신설 제안)**
> 입자형 아이템(FX)의 **카드**는 한 알이 아니라 **한 무리**를 그린다. 정원(2~4)과 보조색(1개)은
> **카드 그림에 적용하고**, 월드의 **한 알에는 적용하지 않는다**. 규칙 1(획 예산)은 양쪽에 그대로 적용한다.

이 한 줄이 발자국·반짝임·먼지·물방울·나뭇잎 **5종의 정원/보조색 문제를 동시에 닫는다**.
PET은 입자가 아니므로(항상 한 마리) 정원/보조색을 **그대로 지킨다**.

### 4-2. 새 도형 4개

**발자국 — 둥근 점을 버리고 옆에서 본 밑창으로.**
`BuildDot(Stroke*0.9)` → 3점 열린 선. 획 두께가 얹히면 0.96 R × 0.40 R의 납작한 캡슐이 된다.
앞(+x)이 길고 낮고 뒤가 짧고 들려 있어 **진행 방향이 읽힌다**.
```
Sole (열린 3점, 주색)  (−0.40, +0.10)  (−0.02, 0.00)  (+0.56, +0.04)
   변 1.14 획 / 1.69 획 · 잉크 사각형 2.79 획 (현행 1.19 획의 2.3배)
```

**반짝임 — 팔 길이를 다르게 해서 '＋'를 없앤다.**
현행은 가로·세로가 **정확히 같은 길이**라 화면에 뜨는 그림이 더하기 기호다.
```
CrossV (열린 2점) (0, −1.00) (0, +1.00)
CrossH (열린 2점) (−0.68, 0) (+0.68, 0)
```
> ★ **여기가 제안 A의 한계다.** 진짜 반짝임은 갈래 끝이 **점으로 수렴**해야 하는데(39절 원칙 6),
> `LineRenderer`의 캡은 항상 둥글다. **뾰족한 끝은 채운 도형의 꼭짓점으로만 만들 수 있다.** → 제안 B.

**작은공 — 바퀴살을 솔기로.**
현행 `BallSpoke`는 **중심에서 테로 뻗는 반지름**이다. 그건 바퀴(wheel)의 어휘다.
공을 공으로 읽게 하는 것은 **솔기(seam)** — 구(球)의 큰 원이 옆에서 보이는 완만한 호다.
```
Seam (열린 4점, 보조색)  (0, −0.5687)  (+0.2469, −0.2155)  (+0.2469, +0.2155)  (0, +0.5687)
   테 위 두 점을 잇고 +x로 0.28 R 부푼 원호(그 원의 반지름 0.7176 R) · 변 1.25 획
```
회전 가독성은 그대로다(비대칭이라 오히려 더 낫다). 양 끝점이 **테 위에 정확히 얹히므로**
간격은 0 — 규칙 4의 "0 또는 ≥1.5 획" 중 0 쪽이다.

**커서친구 — 한 획을 머리와 꼬리로 쪼갠다.**
크기만 키우면 정원 1개·보조색 0개가 남는다. 화살표를 **머리(주색) + 꼬리(보조색)** 두 조각으로
쪼개면 정원 2 / 보조색 1이 동시에 해결되고, 기하가 뭉개지는 크기에서도 **꼬리가 색으로 읽힌다**.
두 조각은 변 하나를 **공유**하므로 벌어지지 않는다.
```
Head (닫힘, 주색)   (0,0) (0,−1.4000) (+0.3640,−1.0360) (+0.7000,−0.8960) (+1.0920,−0.8680)
Tail (닫힘, 보조색) (+0.3640,−1.0360) (+0.5880,−1.4840) (+0.9240,−1.3440) (+0.7000,−0.8960)
   둘 다 최단변 1.06 획 · 자기교차 없음 · 전체 1.09 R × 1.48 R
```

### 4-2-1. 일부러 붙여 두는 것 — 먼지 두 초승달

두 초승달의 중심선 최소 간격은 **0.48 획**이다. 규칙 4의 "0 또는 ≥1.5획"에서 보면 최악 구간처럼
보이지만, 그 규칙은 **따로 읽혀야 하는 두 조각**에 거는 것이다. 먼지는 반대로 **한 덩어리의 울퉁불퉁한
구름**이어야 하므로 잉크가 겹치는 것이 옳다(획 반폭이 각각 0.5 획이라 0.48 획 간격이면 실제로 겹친다).
읽히는 것은 **위 초승달의 마루 1.06 획**이다 — 그것이 "한 덩어리인데 혹이 있다"를 만든다.
**나중에 이것을 '위반'으로 보고 떼어 놓지 마라.**

### 4-3. 손대지 않는 것

- **풍선** — 현행 그대로 통과한다(최단변 String 1.25 획 / Body 1.11 획, 정원 2, 보조색 1).
- **종이비행기 접힘선** — 현행 `PlaneFold`는 3점인데 그중 두 번째 변
  `(−0.42w, 0) → (−0.75w, −0.62w)`가 **몸 외곽선의 변과 완전히 겹친다**(같은 두 점).
  잉크가 두 번 얹힐 뿐 새 정보가 없다. **2점으로 줄인다**: `(w, 0) → (−0.42w, 0)`.
  이것이 종이비행기의 **용골(keel) 접힘선**이고, 종이의 어휘는 "완벽히 곧은 모서리 + 접힌 자국 하나"다.

## 6. 참고 이미지에서 가져온 것 (Alan Becker 계열, 픽셀 실측)

★ 리더는 이 이미지를 볼 수 없으므로 **본 것을 글과 숫자로 적는다.** 형태는 옮기지 않았다 —
**만드는 방식**만 가져왔다.

측정 대상: `8875f6ce`(노랑/파랑/주황 3인), `23213986`·`5a31dd2c`(빨강/초록 2인, **머리띠·손목띠·발목띠
착용**). 원본 1260×2736. 색 마스크 + 반복 침식(거리 변환)으로 최대 내접원을 재서 획 두께를 얻었다.

### 6-1. 실측 숫자

| 대상 | 실측(px) | 머리 지름 대비 |
|---|---|---|
| 초록 캐릭터 머리 지름 | **172** | 100% |
| 초록 캐릭터 팔다리 획 | **40~44** | 24~26% |
| **머리띠 두께** | **38** | **22.1%** |
| **손목띠 두께** | **34** | 19.8% |
| 노랑 캐릭터 머리 지름 / 몸통 획 | 148 / 42 | 획 = 28% |

파생 비율: **머리띠 ÷ 몸 획 = 38 ÷ 42 = 0.90**, **손목띠 ÷ 몸 획 = 0.81**.

### 6-2. 가져올 만드는 방식 5가지

1. **액세서리는 채운 덩어리다. 윤곽선이 한 줄도 없다.** 머리띠는 머리를 가로지르는 **한 덩어리의
   짙은 띠**이고 테두리가 없다. → 12종이 전부 윤곽선인 지금 상태와 정반대다(5절).
2. **띠는 감싼다.** 머리띠는 머리 폭을 **끝에서 끝까지** 건너지르고 **머리 실루엣이 그것을 잘라낸다** —
   허공으로 삐져나온 끝이 없다. (30종 스펙의 "얹지 말고 감싼다"와 같은 관찰이고, 이번에 숫자가 붙었다.)
3. **팔다리는 뿌리에서 굵고 끝에서 점으로 수렴한다.** 손끝·발끝에 뭉치가 없다.
   → 우리 `LineRenderer`는 균일 폭 + 둥근 캡이라 이걸 **선으로는 못 낸다**. 채운 도형의 꼭짓점만
   뾰족해질 수 있다(제안 B 반짝임의 근거).
4. **머리는 꽉 찬 원반이고, 목에서 몸통과 하나의 덩어리로 이어진다.** (우리 앱은 2026-09-01 P1에서
   이미 머리를 채웠다 — 방향이 맞다.)
5. **색은 정확히 두 값이다** — 몸 색 + 짙은 액세서리 색 하나. 세 번째 색이 없다.
   → 규칙 3-2(보조색 정확히 1개)가 이 관찰과 정확히 일치한다. FX가 보조색을 아예 못 쓰는 것(1-2)은
   그래서 미달이 아니라 **어휘 하나가 통째로 빠진 상태**다.

주황 캐릭터는 머리가 **빈 링**이고 노랑·초록·파랑은 **채운 원반**이다 — 같은 작가가 둘 다 쓴다.
즉 "링이냐 채움이냐"는 이 스타일의 규칙이 아니라 캐릭터 구분 수단이다.

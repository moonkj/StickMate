## 0. R1에서 무엇이 바뀌었나 — **내 설계 2건이 반증됐다. 그대로 적는다**

### 0-1. ✅ 해소 — 우클릭 재개방 근거가 등재됐다

R1에서 내가 P0로 올린 *"36-9에 재개방 근거가 한 줄도 없다"* 는 `ux-designer`가 받아
`UX_RIGHTCLICK_FAN_MENU.md` **§5-0 정정표**로 등재했다. 사용자 지시 원문이 명시됐다:

> **2026-09-05** — *"그냥 캐릭터에서 마우스 오른 쪽 버튼 누르면 촤르륵 펼쳐지게 변경"*

**그리고 폐지 근거 ②가 `dev-platform` 소스 실측으로 반증됐다** — 이것이 내 F3 설계를 무너뜨린다:

```csharp
// Library/PackageCache/com.kirurobo.uniwinc@…/Runtime/Scripts/UniWindowController.cs
void SetClickThrough(bool isThrough) { _uniWinCore?.EnableClickThrough(isThrough); … }
```
`EnableClickThrough`는 **창 전체 속성**이라 버튼을 가리지 않는다.
⇒ **커서가 캐릭터 위에 있는 매 순간 우리 창은 이미 클릭관통이 꺼져 있고 우클릭을 삼키고 있다.**
지금은 그것으로 아무것도 안 할 뿐이다. **비침해 추가 비용 0 pt².**

★ **내 R1 F3(「거부된 프레임에 `LocalClickCaptureGate` 락을 요청하지 않았다」)은 틀린 것을 재고 있었다.**
관통 해제는 **락과 무관하게 히트테스트가 상시로** 한다. F3을 §1-1-A에서 **F3′로 교체**했다.

### 0-2. ✅ 범위 확정 — **교체가 아니라 추가다. 톱니는 남는다**

리더 결정. 진입점이 **둘**이 되고, `GearRadialMenuWidget`은 **인스턴스가 하나**다.
⇒ R1의 F23(「두 부채꼴이 동시에 안 보인다」)은 **구조적으로 불가능한 것을 재던 빈 조건**이었다.
진짜 계약은 **재앵커**(접고 그 자리에서 다시 편다)이고, `ExclusiveSurfaces`는 이 문제를 **풀지 못한다**
(같은 하나의 표면이 앵커만 바꾸는 것이라 배타 규약의 대상이 아니다). → **F23′로 교체.**

### 0-3. ★★ 자백 — **내 R1 E11/E12(망토 클램프)는 거짓 통과 설계였다**

`design-motion` §2-5가 반증했다. 현행 `ClampAboveFloor(pts, floorY)`의 `floorY`는 **스칼라**인데,
밑단 점이 사는 컨테이너는 **상체와 함께 회전한다**(`landingCrouchTorsoPitchDegrees 22°` /
`…BraceDegrees 30°`, 피치와 깊이가 같은 램프에서 나와 **동시에 최대**가 된다).

```
올바른 바닥선:  floorY(p.x) = HipY + ( sinθ·p.x − HipY − s·b ) / cosθ      ← p.x의 1차 함수
현행 코드    :  floorY      = −s·b                                          ← θ=0 에서만 옳은 특수해
```

| 피치 | 웅크림 | 밑단 뒤끝 | 밑단 앞끝 |
|---|---|---:|---:|
| 22° | 최대 | +4.63 pt 뜸 | **−3.00 pt 관통** |
| 30°(버팀) | 최대 | +7.06 pt 뜸 | **−3.84 pt 관통** |

**내 R1 단언은 「`moved > 0` 이고 받친 점의 y == floor」였다. 그 단언은 위 3.00pt 관통을 전부 초록으로 통과시킨다** —
스칼라 floor 기준으로는 정확히 y == floor 이기 때문이다. **기준이 틀렸는데 측정은 완벽했다.**
이 저장소의 공통 형태(*"실패한 측정과 성공한 측정이 똑같이 생겼다"*)를 내가 그대로 밟았다.
→ **E11~E13을 E11′~E15′로 전면 개정**(§2-1-c).

### ★★ 정정 1건 — R20 문서가 **존재하지 않는 심볼**을 인용했다

이것이 CLAUDE.md가 경고한 **죽은 니들** 그 자체다. 겨눌 것은 위 **5개 실제 분기**다.

### 0-5. ★ 정정 2건 — 인계본의 수와 실측이 갈렸다

착수 전 심볼 전수 확인(FP-19를 나 자신에게 먼저 적용)에서 나왔다.

**(가) 허가 발급 지점은 1곳이 아니라 2곳이다.**
UX §5-6은 *"허가 발급 지점 1곳 → 2곳"*(톱니 클릭 하나)이라 적었다. 실측:

```
$ grep -rn "TryGrantUserSummon" --include=*.cs Assets | grep -v /Tests/
  Core/StickmanAgent.cs:320            ← 정의부
  Interaction/InfoGearIconWidget.cs:1601   _agent.TryGrantUserSummon("톱니 클릭");
  Interaction/SettingsWindow.cs:586        _agent.TryGrantUserSummon($"설정창 열기({source})");   ← ★ 누락
```

⇒ **2곳 → 3곳**이 맞다. 이 수가 틀리면 F20c가 *"정확히 2곳"*을 요구해 **정상 코드를 빨갛게 만든다**
(그리고 다음 사람이 `SettingsWindow`의 발급을 「잘못 들어간 것」으로 읽고 지울 수 있다).
향후 톱니 제거 라운드의 「탈영구 재배치」 대상도 **2곳이 아니라 3곳**이다.

**(나) 내 프로브가 한 번 죽었다 — 그대로 적는다.**
1차 감사 스크립트에서 `n=$(... | wc -l)` 이 빈 문자열을 반환해 `[ "$n" = "0" ]` 이 항상 거짓이 되었고,
**23개 심볼 전부가 ✓로 찍혔다 — `IsTransparentLens`(실제 0건)까지 포함해서.**
가짜 심볼(`ZzzNotARealSymbolQqq`)을 음성 대조로 넣어 두지 않았으면 **못 봤다.**
⇒ **§0-6 감사 스크립트에는 가짜 심볼 1개를 상설로 넣는다.**

InteractiveScreenRect = fanVisible ? Union(IconScreenRect, _menu.UnionScreenRect) : IconScreenRect;

- 2026-09-05에 톱니가 「평상시 숨김」이 되면서 `IconScreenRect`는 **넓이 0**이 됐다(`:1071~1073`).

⇒ **부채꼴이 떠 있는 동안, 부채꼴과 화면 우상단 사이의 «보이지도 않는 띠»가 사용자의 클릭을 먹는다.**
절대 불변 원칙 2(비침해) 정면 위반이다.

★ **640×480 배치모드에서 2.31배(초과 40,730px² = 화면의 13.3%)다. 실기에서는 더 커진다** —
번지는 넓이는 **«부채꼴과 우상단 사이의 거리»**에 비례하고, 그 거리는 화면이 클수록 커진다.
최악은 캐릭터가 좌하단에 있을 때로, 그때 합집합은 **화면 대각선 거의 전부**를 덮는다.

**같은 뿌리의 두 번째 자리**(같이 고쳐야 한다): `GearRadialMenuWidget.cs:1404~1407`의
`UnionScreenRect`는 **버튼이 전부 알파 0인 프레임**(펼침 첫 프레임 · 접힘 마지막 프레임)에
**`_gearCenterPoints`에 있는 넓이 0 사각형**이 된다. 그때도 `fanVisible == true`라 위 `Union`이
**두 «점»의 경계상자**를 만든다.

**제안(프로덕션 소유자 = `coder-ui`. 나는 고치지 않았다)**

```csharp
// 넓이 0인 쪽은 합집합에서 뺀다 — «없는 사각형»이 위치만으로 차단막을 끌고 가면 안 된다.
bool gearBox = IconScreenRect.width > 0f && IconScreenRect.height > 0f;
bool fanBox  = fanVisible && _menu.UnionScreenRect.width > 0f && _menu.UnionScreenRect.height > 0f;
InteractiveScreenRect =
      gearBox && fanBox ? Union(IconScreenRect, _menu.UnionScreenRect)
    : fanBox            ? _menu.UnionScreenRect
    : IconScreenRect;
```

이 테스트는 **고쳐지면 저절로 초록이 된다**(배수 하한 `BlockerAreaTolerance = 1.10`). 낮추지 마라 —
«몇 픽셀 여유»가 문제가 아니라 **자릿수가 달라졌는가**가 문제다.

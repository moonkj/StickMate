## 5-1. ★★ 규율 ι — **고를 표면이 0인 항목은 프레임에 넣지 않는다** (판정: **채택**)

### 왜 이것이 이 자리의 핵심 논거인가

> **골든은 「카탈로그와 같은가」만 본다 ⇒ 골든 초록이 스크린샷 합격을 보증하지 않는다.**

같은 병이 **이미 출하됐다** — 「톱니 링」은 문서가 **없는 부품**을 「✔ 채택」으로 들고 있었고 형상 게이트 다섯이 그것을 **구조적으로 못 봤다.**
데이터가 실재하면 골든은 초록이다. **화면에 고를 것이 있는지는 골든이 묻지 않는다.** 그 간극을 메우는 것이 이 자리의 존재 이유다.

### 근거 (내가 다시 쟀다)

| 사실 | 값 | 앵커(고정 문자열 · `-F`) |
|---|---|---|
| 은퇴 술어 | `IsRetiredSlot(slot) => slot == EquipmentSlot.Hair` | `Core/EquipmentModel.cs` 1건 |
| 은퇴 슬롯 수 | **1개**(Hair뿐) | 같은 술어 |
| HAIR 애셋 | **6종**(`slot: 4` 6개 = `look_hair_*` 6파일) | `Assets/_Project/Resources/Items/` |
| 착용·복원 차단 | 같은 술어에서 막힌다(항상 미착용으로 연다) ⇒ **몸에도 안 그려진다** | `IsRetiredSlot` 호출부 |
| 잠금 | **384줄** | 파일명 `RetiredSlotSurfaceTests.cs` |
| ★ 술어 도입 시각 | **2026-09-06 13:32** — **두 빌드보다 앞** | ⇒ 배포 Windows 빌드에서도 **이미 표면에서 빠져 있다** |

★ **내 첫 계수 2건이 틀렸고 전달값이 옳았다**: HAIR를 9로 센 것은 **slot 0(Head)을** 센 것이고, 12로 센 것은 **`.asset.meta`를 겹쳐 센 것**이다. 슬롯 서수를 `FirstAppearanceSlot`에서 잘못 유도했다. **Hair는 slot 4다.**

### 합격·불합격의 숫자 기준

1. **요청서의 대상 수 = 프레임에 실제로 뜬 물건 수**(차 **0**). 다르면 **판정 불가**이고 사유는 「고를 표면이 0인 항목을 요청했다」.
2. 프레임 목표 목록의 분모는 **화면 분모**(`ItemCatalog.ListedEquipmentCount`)를 쓴다 — 애셋 65도 골든 54도 아니다.
3. 은퇴 슬롯 물건이 프레임에 **하나라도** 잡히면 **불합격**이다. 그것은 되살아난 표면이므로 **별건으로 신고**한다(캡처 결함이 아니다).

### 대가 — 적어 둔다

- 촬영 대상이 **줄어든다**(최소 6종). 「42종을 다 찍자」는 요청서는 이 규율 아래에서 **성립하지 않는다**.
- ★ **은퇴 목록을 계속 추적해야 규율이 산다 — 놓치면 조용히 죽는다.** 추적 앵커는 `IsRetiredSlot`(기대 **1건**)과 잠금 파일 `RetiredSlotSurfaceTests.cs`다. 은퇴가 **늘면** 프레임 목표에서 빼고, **줄면** 다시 넣는다.
- 이 규율은 **부재 단언**이라 썩으면 조용히 초록이 된다 ⇒ 회차마다 위 두 앵커를 **양성 대조와 함께** 다시 센다.

### 버리는 조건

**은퇴 슬롯이 0**이 되면(= `IsRetiredSlot`이 항상 거짓) 이 규율을 버린다. **현재 1개라 살아 있다.**

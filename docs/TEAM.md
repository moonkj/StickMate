## 2. 팀별 역할

### 🎯 기획 · 총괄 (3)

| 담당 | 범위 | 하지 않는 것 |
|---|---|---|
| **리더 — Architect**<br>(현재 세션) | 통합 · 최종 판정 · Phase 게이트 · `process.md`/`Tasklist.md` · **유일하게 커밋한다** | 설계 세부를 대신 하지 않는다 |
| `game-architect` | 시스템 간 정합성, 기술 구조 확장성, 신규 기획 ↔ 기존 구조 충돌, 착수 순서, **되돌릴 수 없는 결정 식별** | 화면·조형·수치·구현 |
| `design-systems` | 스탯 / 등급 / 세트 시너지 / 재화 경제의 **수치** — 임계값·상승폭·획득량·가격·소프트캡 | 화폐 단위가 아닌 실제 달러(→상품전략) |

### 💰 상품 전략 (1)

| 담당 | 범위 |
|---|---|
| `product-strategy` | 유통 채널(스팀 / MS스토어 / 맥앱스토어), DLC 구성·가격, 무료·유료 경계, 출시 순서 |

`design-systems`가 "동전 몇 개"를 정하면, 이쪽은 **"몇 달러"**를 정한다.

### 📣 마케팅 (1)

| 담당 | 범위 |
|---|---|
| `marketing` | 홍보 소재, 스토어 페이지, 스크린샷·GIF 구성, 개발일지·커뮤니티 |

**거짓 소재 금지.** 실제로 되지 않는 기능을 스크린샷으로 만들지 않는다.
캡처는 **실제 빌드**에서, **깨끗한 테스트 환경**에서(남의 창 제목·파일명이 찍힌다).
외부 게시는 전부 리더 승인 후 사용자가 한다.

## 3. 유기적 운영 — 라운드 사이클

```
 사용자 요구
      │
      ▼
 ① 기획·총괄  ── game-architect가 기존 구조와 충돌하는지 먼저 본다
      │             (되돌릴 수 없는 결정이면 여기서 멈추고 리더가 사용자에게 묻는다)
      ▼
 ② 설계     ── 디자인 7인 / design-systems. 서로의 산출물을 읽고 교차 검토해 올린다
      │
      ▼
 ③ 구현     ── coder / dev-platform. 리더가 파일을 갈라 준다
      │
      ▼
 ④ 테스트   ── test-engineer(기능) · qa-regression(회귀) · debugger(원인)
      │
      ▼
 ⑤ 검증     ── verify-change. 보고서의 각 주장을 독립적으로 다시 잰다
      │
      ▼
 ⑥ 판정     ── 리더. 통과하면 커밋, 아니면 해당 단계로 반려
      │
      ▼
 ⑦ 사용자 검증 ── 페르소나 3인 병렬. 의견은 리더가 받아 담당자에게 배분
```

**반려는 위로만 간다.** ⑤에서 걸리면 ③ 또는 ②로, ④에서 걸리면 ③으로.
담당자끼리 직접 되돌리지 않는다.

★ **반려를 받으면 지목된 줄이 아니라 「같은 경로가 닿는 문장」을 한 번에 전수한다** (2026-09-15 보강 · 리더 자백 포함).
코드 사실 하나(예: Windows 전경 판정)가 문서 여러 곳의 전제를 바꾸면, 지적받은 곳만 고치는 한 검증이 계속 돈다.
그 경로가 닿는 문장을 **해당 문서 전체에서** 먼저 찾아 한꺼번에 고친다. **리더 브리프도 지목 단위가 아니라 경로 단위로 쓴다.**
- 찾는 법: 먼저 코드에서 그 경로가 바꾸는 **사용자 표면**(자동으로 뜨는 창·카드, 설정 창 재오픈, 트레이 메뉴 항목 등)과 **입구**를 목록으로 뽑는다.
  그다음 각 항목의 화면 이름·용어를 **고정 문자열로 해당 문서 전체에서 세고**(아래 「12번째 형태」 같은 가족 보강 규칙 5), 걸린 줄을 전부 직접 읽는다.
  근접 스캐너의 「참조 있음」은 판정이 아니다 — 5차에서 스캐너가 행 근접으로 오탐했고, 직접 읽어 정정했다.
- 사고: 매뉴얼 01·03이 verify-change **5차**까지 돌았다. manual-writer는 같은 전제 3곳을 추가로 발견하고도 미수정으로 남겼고,
  5차가 같은 경로의 다른 문장(설정 창 자동 재오픈)에서 또 누락을 찾았다.
  리더 판정 원문: 「원인은 「같은 경로가 닿는 문장」을 한 번에 전수하지 않고 지목 단위로 고친 것(리더 브리프도 지목 단위였음)」.
- 잡은 것: verify-change 5차가 지적 목록이 아니라 코드 경로를 따라 문서를 다시 읽었다.
- 근거(`Tasklist.md` 2026-09-15, 고정 문자열 앵커): `같은 전제 3곳 추가 발견(미수정)` · `설정 창이 발표 화면 위로 자동 재오픈` · `행 근접으로` · `매뉴얼 순환이 5차째`
- 관계: 새 절이 아니라 이 반려 규칙의 보강이다. 아래 「플랫폼 동시 검토」의 「나중에 맞추자 금지」와 같은 뿌리다.

★ **플랫폼판 — 「유일한 입구」·「입구 0」·「항상」 같은 전칭 판정은 세계별 경로를 전수한 뒤에만 쓴다** (2026-09-15 보강, 위 반려 규칙의 플랫폼판).
최소한 macOS / Windows / Windows인데 트레이를 끈 경우 / iPad·iPhone(스크린샷 백드롭 모드) / 가출 같은 캐릭터 상태 세계를 나눠 입구를 센 다음에 쓰고, 한 세계에서만 참이면 그 세계를 문장에 적는다.
어떤 세계에 그 기능이 없으면 목록에서 빼지 말고 「해당 없음 확인」과 확인 방법을 적는다.
- 사고: F-6 2차에서 game-architect의 「대기 톱니 = 몸 없는 세계의 유일한 마우스 입구 / 바꾸면 입구 0」이 반려됐다.
  Windows 사용자 숨김에는 트레이 메뉴(다시 보이기·설정 열기)가, 가출 세계에는 간식 클릭과 「찾기」 좌클릭이 남아 있었다.
  코드 자신이 `InfoGearIconWidget.cs` 주석에 그 구멍이 macOS 전용이라고 적어 두고 있었다(원문은 굵게 태그가 끼어 있어 문장 통째로는 고정 문자열로 안 걸린다. 앵커는 `macOS 전용`).
  결론(「정리하지 마라」)은 유지되고 근거가 macOS 사용자 숨김 한정으로 좁혀졌다.
- 잡은 것: verify-change 2차가 판정 문장을 세계별 입구 코드(트레이 정책·가출 렌더러·클릭 판정)와 하나씩 대조했다.
- perf-doc 원 코드 재확인: 그 주석의 `macOS 전용` 1회 · `Interaction/RunawayDirector.cs`에 `Suspend(` 0회(양성 대조 `Core/StickmanAgent.cs` 12회) ·
  `Interaction/StickmanClickHitbox.cs` 주석 「가출 은신은 Suspend를 쓰지 않으므로」 실재 · 트레이 정책에 「다시 보이기」·「설정 열기」·`STICKMATE_NO_TRAY_ICON` 실재.
  iPad·iPhone 세계는 이 사고에서 **미확인**이다. 톱니 위젯·트레이 정책·가출 두 파일에 `UNITY_IOS`·`UNITY_IPHONE` 분기가 0이라 컴파일에서 빠지지 않으므로,
  「해당 없음」을 코드 가드만으로 단정할 수 없다(같은 검색의 양성 대조: 실제 `#if UNITY_IOS` 분기가 있는 스크립트는 1개(`StickmanAgent.cs`, `#if`·`#elif` 2줄)이고, `ScreenshotBackdropPlatformService.cs`는 주석 언급뿐이다).
- 근거(`Tasklist.md` 2026-09-15): `가출 세계엔 간식 클릭` · `찾기 좌클릭 생존` · `세계별 입구 표`

리더에게 올릴 때 **"상대 팀 산출물의 어느 지점과 어떻게 맞물리는가"**를 반드시 적는다.

| `design-motion` → `coder` | 모션 설계가 **상태의 수평 이동 소유권**을 규정한다. 빠뜨리면 미끄러진다 |
| `design-narrative` → `design-motion` | 대사 노출 시간이 그 상태 지속보다 길면 잘린다 |

| `qa-regression` → 전원 | **누구 라운드가 무엇을 깼는지**를 그 라운드에 알린다 |
| `verify-change` → 리더 | 재현 안 되는 주장만 올린다. 판정은 리더 |

## 4. 전원 공통 규칙

### 절대 금지
- **`driver.sh stop`과 전역 단축키 `Q`** — 전역이라 **사용자가 쓰는 인스턴스까지 함께 죽는다**
- **앱 실행·빌드·Unity 배치모드를 리더 승인 없이** — `Library/` 락이 다른 라운드를 깬다
- **다른 담당자에게 직접 지시** — 전부 리더를 거친다
- **`Tasklist.md` 수정** — 리더 소유
- 디자인·기획·검증팀은 **프로덕션 `.cs` 수정 금지**

### ★ 거짓 통과 방지 (2026-09-02 하루에 9건이 나왔다)

> **실패한 측정과 성공한 측정이 똑같이 생겼다.**

| # | 실제 사고 | 규칙 |
|---|---|---|
| 1 | `-runTests`에 `-quit`을 같이 줘서 **0건 실행 + 종료코드 0** | `-quit` 금지. 콤마 구분 필터도 같은 증상 |
| 2 | **이틀 전** 결과 xml을 새 결과로 읽음 | 결과 파일은 **먼저 지우고** mtime·testcasecount 확인 |
| 3 | **하루 전** Player.log를 현재 상태로 읽음 | 드라이버 로그와 사용자 인스턴스 로그를 구분 |
| 4 | `strings`로 .NET(UTF-16) 문자열을 찾아 "0건 = 깨끗" | **모든 "없음" 판정에 양성 대조**. 하나라도 깨지면 그 파일의 0건 전부 무효 |

### 동시 진행
**리더가 파일을 갈라 준다.** 겹친 채로 돌면 한쪽이 다른 쪽의 작업 중 파일을 커밋하거나
컴파일 불가 트리에서 검증하는 사고가 난다(2026-09-02 두 건 실제 발생).

★ **에이전트의 git 호출은 전부 `git --no-optional-locks …`로 한다 — 수동으로 치든 스크립트에서 부르든 같다. 단 옵션은 필요조건일 뿐이다: `diff`는 옵션을 붙여도 인덱스를 쓴다** (2026-09-15 보강 · 범위 확대).
plain `git status`는 작업 트리 파일의 stat 정보가 바뀌어 있으면 `.git/index`를 고쳐 쓰고(그동안 `index.lock`), 그 순간 리더 커밋과 경합한다. plain `git diff --stat`도 인덱스를 고쳐 쓴다.
옵션은 **git 전역 옵션 자리**(`git --no-optional-locks status`)에 둔다 — 하위 명령 뒤(`git status --no-optional-locks`)에 두면 알 수 없는 옵션 오류다.
git 명령이나 옵션을 **셸 변수에 담아 부르지 않는다.** zsh는 변수를 낱말로 나누지 않아 호출 전체가 command not found가 되고, 그 빈 출력이 「diff 0」·「삭제 0」처럼 보인다.
- ★ **이 옵션이 막는 것은 `status`의 인덱스 갱신뿐이다. `git diff`는 옵션을 붙여도 인덱스를 고쳐 쓴다**(perf-doc 실측: git 2.50.1(Apple Git-155), 명령마다 새 임시 저장소에서 파일 stat만 바꾼 뒤. verify-change가 trace2 `do_write_index`·inode·upstream v2.50.1 소스·문서로 재현했다. 소스 판정은 upstream 기준이고 Apple 포크 소스는 미확인, Git for Windows는 미확인).
  `git --no-optional-locks diff` · `diff --stat` · `diff --numstat` · `diff HEAD --stat`, 그리고 환경 변수 `GIT_OPTIONAL_LOCKS=0`을 준 `git diff --stat`에서 모두 인덱스 해시·mtime이 바뀌었다(`diff --stat`은 3회 반복 동일).
  바뀌지 않은 것: `--no-optional-locks`를 붙인 `status` · `rev-parse` · `log` · `ls-files` · `diff-files` · `diff-index`, 그리고 stat이 안 바뀐 저장소의 `diff`.
  실저장소에서 차분이 필요하면 **배관 명령**을 쓰거나 복사본에서 돌린다: `git --no-optional-locks diff-files --numstat`(작업 트리 대 인덱스) · `git --no-optional-locks diff-index HEAD --numstat`(작업 트리 대 HEAD).
  ★ **차분 판정은 `--numstat`(또는 내용 기반 `-p`)으로만 한다. 이름 목록·종료코드로는 판정하지 않는다.** 배관 명령은 인덱스를 고치지 않는 대신 stat만 바뀐 파일을 출력 형식에 따라 다르게 보고한다.
  perf-doc 실측(같은 조건): `--numstat`·`-p`는 줄 없음 / `--name-only`·`--name-status`·형식 없음(raw)은 그 파일을 변경으로 보고 / `--quiet`·`--exit-code`는 rc 1.
  세 번째 우회: `git --no-optional-locks -c diff.autoRefreshIndex=false diff`는 인덱스를 쓰지 않았다(`--stat`·`--numstat` 둘 다 줄 없음).
  문서 근거(upstream v2.50.1, 줄바꿈을 이어 고정 문자열로 확인): `git.adoc`의 `GIT_OPTIONAL_LOCKS` 설명 「this will prevent `git status` from refreshing the index」 /
  `config/diff.adoc`의 `diff.autoRefreshIndex` 설명 「affects only `git diff` Porcelain, and not lower level `diff` commands such as `git diff-files`」. 설치된 Apple git 매뉴얼 페이지에도 같은 문장이 있다.
  소스 근거(upstream v2.50.1, perf-doc 확인 범위는 두 파일): `builtin/diff.c` 전체에 `use_optional_locks` 0회(같은 파일 `refresh_index_quietly` 2회로 검색 생존) · `builtin/commit.c`에서는 `cmd_status` 안 1곳.
  예외: 리더 커밋의 스테이징 목록 대조 `git --no-optional-locks diff-index --cached --name-only HEAD`는 인덱스와 HEAD만 비교해 작업 트리 stat과 무관하다(실측: stat만 바꾼 파일은 안 나오고 스테이징한 파일만 나옴).
- **남의 `index.lock`이 있으면** `status`와 `diff`는 인덱스 쓰기를 **조용히 건너뛰고 rc 0**(stderr 없음)으로 끝나고, 같은 순간 커밋 쪽 `git add`는 **rc 128**로 실패한다.
  경합의 피해는 읽은 쪽이 아니라 **커밋하는 쪽**에 난다.
- 도구 머리에 「파일을 쓰지 않는다」고 적었으면 **실행 전후 `.git/index` 해시·mtime 대조**로 그 주장을 확인한다.
  ★ 이 대조는 **실저장소가 아니라 복사본**에서 한다. 실저장소 인덱스는 리더 git 작업으로도 바뀌어 오탐한다.
- 사고: 약속 테스트 스캐너의 머리 주석은 「파일을 쓰지 않는다」였는데, verify-change가 `.git`까지 복사한 사본에서 돌려 보니 plain `git status`가 인덱스 해시를 바꿨다
  (`--no-optional-locks` 호출과 `rev-parse`는 불변). 리더 판정: 수정 전까지 실저장소에서 스캐너 실행 금지(복사본만).
  ★ perf-doc 자백: 이 규칙 초안을 쓰던 라운드 앞부분에 **실저장소에서 수동으로 plain `git status --short`를** 여러 번 불렀다.
  리더는 커밋 전후와 겹쳤을 수 있으나 잠금 파일 없음 확인 뒤 커밋이 정상 완료돼 피해 0으로 판정했고, 이후 전 에이전트 브리프에 `--no-optional-locks`를 명시했다. 그래서 범위가 스크립트에서 **모든 git 호출**로 넓어졌다.
  검증 인스턴스 여러 곳에서는 zsh 변수에 담은 git 호출이 command not found로 죽은 채 빈 출력을 냈다.
- 잡은 것: verify-change가 **모든 실행을 복사본에서** 하고 실저장소 인덱스 mtime 불변을 함께 확인한 설계.
  perf-doc 재현(임시 저장소, git 2.50.1): 파일 stat만 바꾼 뒤 plain `status` → 인덱스 해시·mtime 변경 / `--no-optional-locks status`·`rev-parse` → 불변 / 하위 명령 뒤 위치 → rc 129.
  verify-change TEAM 초안 검증 재현: plain `diff`도 인덱스를 고침 · 남의 잠금이 있으면 커밋 쪽 rc 128.
  `--no-optional-locks`를 붙인 `diff`도 인덱스를 고친다는 것과 남의 잠금 아래 `status`·`diff`의 rc 0은 perf-doc 실측이고, verify-change 재검증이 trace2 `do_write_index`·inode·upstream v2.50.1 소스·문서라는 다른 방법으로 재현했다
  (git 2.50.1 Apple · 소스는 upstream 기준이고 Apple 포크 소스 미확인 · Git for Windows 미확인). 출력 형식별 차이와 `diff.autoRefreshIndex=false` 우회도 같은 재검증에서 나왔고 perf-doc이 다시 쟀다.

## 5. 정직성 규칙

- **확인 못 한 것은 "미확인"으로.** 추측으로 메우지 않는다.
- **"고쳤다"고 쉽게 쓰지 않는다.** 실기 검증이 불가능하면
  "이렇게 동작할 것으로 판단한다, 실기 미확인"이 정직한 상태다.
- **자기 산출물의 거짓 통과를 발견하면 그대로 보고한다.** 이 저장소에서 가장 값진 보고들이
  전부 그것이었다 — 양성 대조가 처음에 초록이었다는 자백, 자기 게이트의 구멍을 스스로 찾은 것.
- **반증되면 반증됐다고 쓴다.** 리더의 가설도 예외가 아니다.
- **옛 판정은 지우지 않고 취소선으로 남긴다 — 대상은 「커밋된 판정」이다** (2026-09-15 범위 명시).
  목적이 **공개된 판정의 이력 추적**이라서다. 한 번도 커밋되지 않은 초판의 문장을 본문에 취소선으로 되살리지 않는다.
  대신 문서 끝에 **「초판(미커밋) 대비 정정 기록」 절**을 두고 초판 요지 → 정정 → 근거(검증 지적 번호)를 남긴다.
  - 사고: verify-change 2차가 `TASKBAR_LOGOFF_ORDERING.md`에서 옛 판정 8문장이 취소선 없이 제자리 교체된 것을 지적했다.
    그런데 그 파일은 미추적이라 첫 판이 git에 한 번도 없었다. 리더 판정: 보존 규칙의 목적은 커밋된 판정의 이력 추적이므로
    인라인 취소선 복원은 요구하지 않고, 정정 기록 절로 추적성을 남긴다. game-architect가 문서 끝 부록으로 반영했다.
  - 잡은 것: verify-change 2차의 옛 문장 대조(원문 기록은 1차 보고뿐이었다).
  - 앵커와의 관계(리더 판정, 이 규칙 우선): 커밋된 옛 판정 문장 안의 백틱 앵커는 **취소선 안에 그대로 둔다.**

## ★ 경쟁 → 채택 → 집단 고도화 (사용자 지시 2026-09-02)

> **"DLC 팩 같은 건 디자이너별로 각각 일을 줘서 경쟁을 붙여 고도화하는 형태로 해줘"**
> **"경쟁 후 결과물이 잘 나오는 걸로 채택하고, 그 채택된 건 다시 디자이너 인원들이 붙어서 추가 고도화"**

**큰 조형·컨셉 과제는 2단계로 돈다. 한 사람에게 통째로 주지 않는다.**

### 1단계 — 발산(경쟁)
**같은 브리프를 여러 담당에게 동시에 준다.**
- ★ **서로의 제안을 읽지 못하게 한다.** 독립이라야 경쟁이 성립한다
  (오늘자 경쟁 문서는 읽기 금지, 과거 실측 자료는 읽어도 된다)
- ★ **"뽑아 달라"고 쓰지 말라고 명시한다. 약점을 숨기면 감점**이라고 미리 알린다
- ★ **판정 기준을 브리프에 미리 공개한다.** 나중에 만든 기준으로 고르면 그건 판정이 아니라 취향이다
- **경쟁자는 축이 서로 달라야 한다.** 같은 질문에 **다른 자**를 대는 구성이라야 비교가 값을 한다
  (예: `design-equipment`는 실루엣 예산 도구, `design-character`는 "여전히 스틱메이트로 읽히는가")

### 2단계 — 수렴(집단 고도화)
**리더가 근거로 채택안을 고른 뒤, 그 하나에 디자이너 전원이 각자의 축으로 붙는다.**
- 조형(`design-equipment`·`design-character`·`design-art`) · 모션(`design-motion`) ·
  어조(`design-narrative`) · 소리(`design-sound`)
- ★ **진 제안을 버리지 않는다** — 진 쪽의 강점을 채택안에 흡수할 수 있는지 리더가 지목한다
- ★ **채택 근거를 문서에 남긴다.** 왜 이겼고 왜 졌는지가 없으면 다음 경쟁이 같은 것을 반복한다

### 리더가 지키는 것
- **1단계 중에는 채택안을 암시하지 않는다.** 힌트를 주면 경쟁이 아니라 유도가 된다
- **2단계 전에 판정을 먼저 공개한다.** 순서가 뒤집히면 고도화가 아니라 사후 정당화가 된다
- ★ **1단계에서 나온 실측은 진 제안 것이라도 살린다** — 측정은 취향이 아니다

## ★ 거짓 통과 12번째 형태 — **대소문자가 프로브를 죽인다** (2026-09-02, 리더 자신이 당함)

리더가 `coder-ui` 라운드를 **"아무것도 착지하지 않았다"**로 판정하고 재시작시켰다. 근거는 이것이었다:

```bash
git status --short Assets/.../Interaction/TodoPostitWidget.cs    # ← 소문자 i
# (출력 없음, rc=0)  → "깨끗하다 = 미착지"로 읽었다
```

**실제 파일명은 `TodoPostItWidget.cs`(대문자 I)다.** 그리고 그 라운드는 이미 **208줄을 착지시켜 놓았고**
배치모드 초록 기록(`docs/verify/runs/ui-postit_play.xml`)까지 있었다.

### 왜 안 걸렸나 — 두 도구가 대소문자를 다르게 취급한다
| 도구 | 대소문자 | 결과 |
|---|---|---|
| macOS 파일시스템 · `grep` | **무시** | 잘못 쓴 이름으로도 **정상 동작**했다(`:319`를 실제로 찾아냈다) |
| `git`(인덱스) | **구분** | 매치 0건 → **빈 출력 + rc=0** |

**같은 턴에 한 도구는 성공하고 한 도구는 조용히 실패했는데, 리더는 둘 다 성공으로 읽었다.**
`git status`의 "깨끗함"과 "그런 경로가 인덱스에 없음"이 **출력상 완전히 동일하다.**

### 규칙
1. **`git` 계열에 경로를 직접 타이핑하지 마라.** `git --no-optional-locks status --short -- <디렉터리>`(⑨에 맞춰 정정)로 받아 **목록에서 고르거나**,
   `ls`/`grep -l`이 돌려준 경로를 **그대로 붙여 넣어라.** 손으로 옮겨 적는 순간 이 함정이 열린다.
2. **"깨끗하다"를 결론으로 쓰려면 양성 대조를 붙여라** — 같은 명령이 **다른 파일에서는 실제로 M을 출력하는지**

⇒ **「`set -e`가 없어서」라는 진단으로 다른 스크립트를 고치지 마라. 그 병이 아니다.**

### ★ 공개 저장소 규칙 — 사용자명·기기 정보를 새로 싣지 않는다 / 남의 scratchpad에 쓰지 않는다 (2026-09-14 security 전수 점검)

2. 검색에 사용자명이 필요하면 실행 시점 `id -un`으로만 얻고, 보고·파일에 옮기지 않는다.
3. **scratchpad는 리더가 브리프에 적어 준 절대 경로만 쓴다** — `ls -d …/*/scratchpad | head -1` 같은 글롭 선택 금지(다른 세션 디렉터리에 쓴 사고 1건).
   ★ **(2026-09-15 보강) 그 안에서도 루트에 쓰지 말고 자기 하위 폴더에만 쓴다**(예: `perfdoc-anchor/`처럼 역할·주제 이름).
   공유 scratchpad 루트는 같은 세션의 모든 에이전트가 함께 쓰고, 같은 이름 파일을 덮어써도 아무 오류가 나지 않는다.

   - 잡은 것: 도구가 아니라 **그 에이전트의 자백**뿐이었다. 덮어쓰기는 흔적을 남기지 않는다.
   - 근거(`Tasklist.md` 2026-09-15): `같은 이름 기존 파일 덮어씀` · `에이전트는 scratchpad 루트가 아니라`
   - 관계: 이 항목(경로는 브리프에서만 받는다)의 보강이다. 「격리 미러 규약」(미러 경로에 라운드 식별자, 남의 미러에 써 넣은 사고)과 같은 뿌리 —

이번 실측이 그 예다: 인계본 조각 **91개 중 44개(48%)**가 우리 출하 배율에서 **존재하지 않는다**(하이라이트 17/17 전멸).
색은 **12개 중 11개**가 우리 대역 밖. 그리고 인계본이 *"흰 선 + 검은 머리로 고정(게임 원본 규칙)"*이라 적었는데
**우리 출하 기본은 검은 선이고 사용자가 고른다** — 그 전제 위에 세운 *"한 톤 밝게"*가 정확히 반대로 작동한다.
⇒ **인계본을 그대로 옮기는 것이 채택이 아니다. 「우리 제약에서 무엇이 깨지는가」를 재는 것까지가 채택이다.**

### ★ 정정 — 페르소나는 `Tasklist.md`에 직접 쓴다 (두 정본 충돌 해소, 2026-09-03)
`CLAUDE.md`가 *"각자의 의견은 `Tasklist.md`의 「페르소나 검증 로그」에 기록되고"*라고 **페르소나의 자리를 이름으로 지목**한다.

### ★ 색 예약 — 등급에 파랑·회색을 쓰지 마라 (2026-09-03 확정)

⇒ 채택안 **D「기본 자리 승계」** — 우선순위 무변경, 마지막 `기본`만 등급이 승계한다.

### ★★ 락 프로브 재정정 3회차 — `-batchmode` 문자열을 요구하면 안 된다 (2026-09-03)
리더가 앞서 `pgrep -f` → `ps -ax | grep "Unity.app/Contents/MacOS/Unity -batchmode"`로 고쳤는데 **그것도 불완전했다.**

`coder-systems` 실측: **프로브가 비었는데 락이 잡혀 있었다.**
```
Fatal Error! It looks like another Unity instance is running   ← 실제로는 잡혀 있었다
종료코드 0                                                      ← 성공과 똑같이 생겼다
결과 xml 미생성                                                 ← 이것만이 유일한 단서였다
```
**`-batchmode` 문자열을 요구하는 프로브는 GUI 에디터나 다른 기동 형태를 구조적으로 못 본다.**

**정본 (3회차):**
```bash
# ★ 2026-09-14 4회차 정정: 파일 「존재」가 아니라 「보유자」를 본다(위 「정정 2」 — 컴파일 에러로 끝난 Unity가 죽은 잠금을 남긴다).
lsof Temp/UnityLockfile 2>/dev/null                                 # 보유 프로세스가 있으면 잡혀 있다(기동 형태 무관)
ps -ax | grep "Unity.app/Contents/MacOS/Unity" | grep -v grep       # -batchmode 요구하지 않는다
# 둘 중 하나라도 있으면 잡혀 있다. 파일만 있고 둘 다 없으면 「죽은 잠금」 — 지우지 말고 기록하고 진행.
```
★★ **그리고 판정은 프로브가 아니라 산출물로 한다** — **결과 xml이 실제로 생성됐는지 먼저 보라.**
Unity는 락 충돌에서 **`Fatal Error`를 찍고도 종료코드 0을 낸다.** 종료코드도, 프로브도 이 실패를 못 잡는다.
**xml 실재 + `testcasecount == total` 확인이 유일하게 믿을 수 있는 판정이다.**

★ 이 항목은 **하루에 세 번 고쳐졌다** — `pgrep -f`(형제 셸 오탐) → `ps -ax ... -batchmode`(기동 형태 못 봄) → 지금.
**프로세스 프로브는 계속 틀린다. 산출물을 봐라.**

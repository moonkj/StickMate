## 2. 자(尺) — 이 문서의 모든 숫자가 서 있는 바닥

```
배율 0.75(출하 기본)
  머리 반경 1 R = 5.8163 pt        머리 지름 = 11.63 pt = 5.82 W
  획 W        = 0.343864 R = 2.00 pt
  1.5 W = 0.515796 R      3.0 W = 1.031593 R
  주인 신장 = 10.34 R = 60.1 pt

카드
  BuildIcon 은 40 viewBox 를 renderSize 로 키우고 획 = 1.7 x (renderSize/40)
  ⇒ 어떤 크기에서도 **획 = 상자의 4.25 %**. 44 px 상자에서 획 = 1.87 px
  ⇒ 40 단위 공간에서 W_card = 1.70, 1.5 W_card = 2.55

규칙(39-6, 기존):
1. 모든 변 ≥ 1.0 W · 도형별 잉크 사각형 ≥ 1.5 W
2. 내부를 보여야 하는 **닫힌 고리**는 최소 개구 ≥ 3.0 W
3-2. 아이템당 **보조색 정확히 1개**
4. 따로 읽혀야 하는 두 조각의 중심선 간격 = **0 또는 ≥ 1.5 W**
5. 아이템당 도형 **2~4개**
6. 쌍별 실루엣 차 ≥ 1.0 W · 자기교차 0

## 3. ★ 이 라운드가 새로 확정한 것 세 가지 (숫자 있음)

### 3-1. **닫힌 고리는 개구 3W 아래에서 「고리」가 아니다 — 막대가 된다**

1차안은 위성 봇을 `a=1.00, b=0.26` 타원 두 개(±34° 거울 대칭)로 잡았다.
**규칙 1·3-2·4·5·6을 전부 통과했고, 실루엣 차도 2.64획로 여유가 컸다.**
그런데 실제 크기 렌더에서 **나비넥타이(X)로 읽혔다**(`r22_pets_sheet.png` 1차판).

```
개구 2b = 0.52 R = 1.51 W = 3.02 pt
획이 위아래로 각각 1.00 pt 씩 먹으므로 남는 구멍 = 1.02 pt
⇒ 3.02 pt 짜리 '고리'는 화면에서 2 pt 막대 한 줄이다
```

**규칙 2가 이미 「지름 ≥ 3W」라고 적혀 있었는데, 그건 원에만 적용돼 있었다.**
타원에서는 **긴 축이 아니라 짧은 축(2b)이 그 규칙의 대상**이다. 아무도 그렇게 적어 두지 않았다.

> **규칙 2-E(신설 제안)**: 닫힌 고리의 판정 치수는 **가장 좁은 개구**다.
> 타원이면 `2b ≥ 3.0 W = 1.0316 R`. 이걸 못 사면 **닫지 말고 열린 호로 눕혀라** —
> 열린 호에는 개구 요건이 없다(고리가 아니라 선 하나이기 때문이다).

이 한 줄이 위성 봇과 블랙홀 코어 **두 종을 동시에 구했다.**

### 3-2. **카드는 크기 차이를 지운다 — 1↔6 구분은 형태로만 가능하다**

카드는 아이템을 상자에 **맞춰 키운다**(`FitFraction`/여백 2.8). 그래서 월드에서 1.47배 차이가
나던 두 펫이 카드에서는 **같은 크기**가 된다. 1↔6 구분 설계는 크기를 근거로 쓸 수 없다.
채택안의 두 펫은 **닫힌 고리 수(2 vs 4)**, **바깥 실루엣(납작한 렌즈 vs 완전한 원)**,
**가로세로비(1.63 vs 1.00)**로 갈린다(§7).

### 3-3. **「눈 두 개」는 이 크기에서 도형 예산이 아니라 산술이 막는다**

눈 한 알이 규칙 1을 지키려면 잉크 사각형 ≥ 1.5 W = 0.516 R.
두 알이 따로 읽히려면 규칙 4로 중심선 간격 ≥ 1.5 W.
바깥 윤곽과도 1.5 W를 띄워야 하므로

```
필요 폭 ≥ 0.516(눈) + 0.516(간격) + 0.516(눈) + 0.516 x 2(양쪽 여백) = 2.58 R = 15.0 pt
```

**주인 머리 지름이 11.63 pt다.** 즉 **눈 두 개를 가진 펫은 주인 머리보다 커야 한다.**

- **꼬마 유령**(폭 3.35 R = 19.5 pt)은 그 값을 산다 → **눈 둘 + 입** ✅
- **스틱 캣**(머리 반경 0.92 R = 5.35 pt)은 못 산다 → **옆모습 눈 하나**로 간다 ✅
  (머리 중심에서 (+0.10,+0.05) R, 지름 0.52 R. 머리 링까지 1.54획 확보)
- 나머지 넷은 애초에 얼굴이 없다

★ 그리고 **눈 두 개를 「한 도형」으로 낼 수 있다** — 2점 선 하나에 폭곡선을 걸어
양 끝만 굵게(1.51 W) 하고 가운데를 0으로 눌렀다. 도형 정원 1칸으로 눈 두 개를 산다.

**「픽셀 점선 꼬리」를 만드는 법 — 폭곡선 계단**

  t 0.4151  1.63
  t 0.4152  0.03      ← 연결선을 눌러 없앤다
  t 0.7036  0.03
  t 0.7037  1.16      ← 비드 1 (지름 0.40 R = 1.16 W = 2.33 pt)
  t 1.0000  1.16
```

### 4-7. ★ 등급 글로우 — `design-art` 인계 반영 (2026-09-06)

`design-art`의 등급 글로우 감사가 확정한 값과 **구현 제약**이다. 이 절은 그쪽 소관 사항을
**내 좌표 사양과 맞물리는 지점만** 옮긴 것이고, hex·세기의 정본은 `design/art/glow.*`다.

| 등급 | hex | peak | 감쇠 | 반경 |
|---|---|---:|---|---|
| 영웅 (미니 도트 드래곤) | `#A78BFA` | **0.63** | `peak·(1−t)²` | **R = 39 pt** (썸네일 높이의 절반) |
| 전설 (블랙홀 코어) | `#FFD375` (= 기존 `RarityColor(Legendary)`, **신규 hex 0개**) | **0.42** | `peak·(1−t)²` | **R = 39 pt** |

#### ★ 절대 하지 마라 — 글로우를 알파 레이어로 그리는 것

> 이 앱은 **투명 오버레이 창**이다. 알파 겹은 α0.5에서 **바탕화면을 25 % 비치게 한다.**
> `UiChrome.RadialGlow()`는 램프를 **알파에 굽는** 함수라 **이 용도로 쓸 수 없다.**

`design-art`가 확정한 구현 형태는 **「썸네일 바탕 스프라이트의 RGB에 구운 불투명 램프」**다 —
**새 `Image` 레이어를 추가하지 않고**, 카드 배경 스프라이트 자체의 색을 굽는다.
구현 담당이 이 문장을 못 보고 알파 오버레이로 만들면 **카드 뒤로 바탕화면이 비친다.**

#### 두 종류의 글로우를 혼동하지 마라 — 자리가 다르다

| | (가) **카드 등급 글로우** | (나) **착용 시 내부 포인트 글로우** |
|---|---|---|
| 어디 | 카드 썸네일 **배경** | 월드의 펫 **도형 하나** |
| 무엇 | 반경 39 pt 방사 램프 | `DragonGlow`(중심 (1.60,1.48) R · 반경 0.26 R) · `BhCore`(중심 (0,0) R · 반경 0.50 R) |
| 소관 | **`design-art`**(위 표) | **이 문서**(자리·반경) + `design-art`(색값) |
| 구현 | 배경 스프라이트 **RGB에 램프를 굽는다** | 보조색 `LineRenderer` 한 줄 |
| 알파 | **금지** | UI가 아니라 월드 선이므로 알파 자체는 가능하지만 **아래 정정 참고** |

#### ★ 정정 — (나)의 「알파 호흡」을 **명도 호흡**으로 바꾼다

앞 절(4-5 · 4-6)에서 글로우 맥동을 알파로 적었으나, 위 제약과 **같은 이유**로 뒤집는다.
투명 오버레이 위에서 알파를 내리면 「빛난다」가 아니라 **「구멍이 난다」**로 보인다.

| 대상 | 기존(폐기) | **채택** |
|---|---|---|
| `DragonGlow` | 알파 0.70 ↔ 1.00 / 1.45 s | **불투명 유지(α = 1)**, 색을 `#A78BFA` ↔ `#A78BFA`를 흰쪽으로 42 % 올린 값 사이에서 **주기 1.45 s**로 왕복 |
| `BhCore` | 알파 0.82 ↔ 1.00 / 2.90 s | **불투명 유지(α = 1)**, `#FFD375` ↔ 흰쪽 28 % 사이 **주기 2.90 s** |

★ **꼬마 유령의 알파 호흡(0.78 ↔ 1.00)만은 유지한다** — 그건 등급 글로우가 아니라
**「반투명한 유령」이라는 조형 자체**이고, 바탕화면이 비치는 것이 의도한 연출이다.
다만 같은 제약군이므로 `dev-platform`의 확인 한 줄을 요청한다(§4-4의 확인 요청과 같은 건).

★ **등호장(equal-arc) 표본이 계약이다.** 균등각 표본은 장축 끝에서 현이 급격히 짧아진다 —

24시간 상주 앱이므로 **빌드 시 한 번만 돌고 결과를 캐시**한다(프레임마다 4096점 적분 금지).

## 11. 재현 방법

```bash
cd design/equipment/verify
python3 r22_pets.py          # 현행 3건 -> 신규 0건 · 실루엣/IoU/규칙4 전수 (교정 내장)
python3 r22_pets_dump.py     # 좌표 전문 + 카드 파츠 + 비교 시트 PNG 재생성
```

산출물
- `r22_pets.out.txt` — 검산 전문
- `r22_pets_coords.txt` — 월드 R 좌표 + 40 viewBox 카드 파츠
- `r22_pets_sheet.png` — 2×3 나란히 비교 시트
  (왼쪽 = **실제 착용 크기 ×4** + 주인 머리 지름 기준자 / 오른쪽 = **카드 44 px 실크기 + ×4**)

★ **시트가 이 라운드의 판정 도구였다.** 1차 시트가 점(속 참)과 폭곡선을 무시하고 균일
윤곽선으로만 그려서 **위성 봇을 나비넥타이로, 드래곤을 산맥으로** 보이게 했다.
렌더러를 구현과 같게 고친 뒤에야 판정이 성립했다.
**판정은 구현과 같은 그림에서만 유효하다** — 이 팀이 이미 한 번 데인 함정
(오프라인 렌더러가 모든 점에 둥근 캡을 찍어 코너 붕괴를 가림)의 재현이다.

★ **최종 판정은 실제 빌드 캡처로만.** 이 문서의 시트는 **오프라인 근사**다.

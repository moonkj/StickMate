발단: `manual-writer` 보고 — *"가출은 배포 기본값에서 스스로 일어나지 않는다"*(`docs/manual/01-where-to-click.md:214-215`)

## 0. 결론 먼저

| 질문 | 답 | 확신 |
|---|---|---|
| 출하 빌드에서 가출이 **스스로** 일어나는가 | **아니다. 원리적으로 불가능하다** — 임계 2.0, 게이지는 `Clamp01`이라 최대 1.0 | 코드·에셋·배선 3중 확인 |

| 그 밖의 진입 경로가 있는가 | **없다** — `ChangeState(Runaway)` 비테스트 호출 4곳 전수, 전부 위 두 경로 또는 가출 내부 재진입 | 전수 |
| **자율 발동 OFF**는 의도인가 | **의도다** — 2026-08-29 사용자 **버그 신고**에 대한 리더 수정(`802143f`). 단 **사용자가 "가출을 꺼 달라"고 요청한 것은 아니다**(`longCapeTripMeanSeconds`와 성격이 다르다) | 커밋·툴팁·Tasklist 3곳 |
| **출하 빌드에서 가출 기능 전체가 죽는 것**은 의도인가 | **의도가 아니다(결정 기록 0건).** 서로의 전제를 깬 두 결정이 합쳐진 결과다 — §2 | 기록 부재 + 전제 충돌 확인 |

**판정 요지**: 수치 결함이 아니라 **결정 공백**이다. 자율 OFF(08-29)는 *"수동 발동은 유지"*를 전제로 했고,

**둘이 서로의 전제를 무효로 만들었는데 아무도 대조하지 않았다.** 되살릴지 여부는 사용자 결정 사안이다(§5).

### 1-4. 가출 진입 경로 전수

`ChangeState(StickmanStateId.Runaway)` 비테스트 호출은 **4곳**이다.

| 위치 | 경로 | 출하 빌드 |
|---|---|---|
| `RunawayDirector.cs:75` | 자율 발동(`Update`) — `:70` 임계 판정 뒤 | **불가**(1.0 < 2.0) |
| `RunawayDirector.cs:179` | `TryForceRunawayNow` | **불가** — 유일한 비테스트 호출자는 `AppControlDirector.cs:685`, 그 앞 `:679` 개발 게이트 |
| `RunawayState.cs:202` | 화해 재진입(가출 **안에서만**) | 가출이 먼저 있어야 함 |
| `RunawayState.cs:232` | 자진 복귀 재진입(가출 **안에서만**) | 가출이 먼저 있어야 함 |

그 밖에 확인한 것:
- `RunawayDirector.ForceTriggerNow`(`:92-99`) — 가출 중이 아니면 `TryForceRunawayNow`로 간다. **비테스트 호출자 0건**(테스트만).
- `ControlAction.Runaway` — 발행처는 단축키 N 한 곳(`AppControlDirector.cs:367`) → `:477-478` → `ForceRunaway`(위 게이트).
- 행동 명령창(`ActionCommandPopover.cs`) — 타일은 활쏘기 · 그라피티 · 창 도둑 · 창 부수기뿐. 가출은 **[돌아와!] 소환 칩만** 있다(가출 중일 때만 보임).
- 플랫폼 계층 — `Platform/` 안 `runaway|가출` 매치는 주석 2파일(`IGlobalKeyStateService.cs:93-97`, `MacOS/MacWindowService.cs:1434`)뿐. **Windows 트레이에 가출 항목 없음.** (양성 대조: 같은 grep이 `Platform/`에서 `StickConfig` 22파일을 잡음)
- 가출 관련 4파일(`RunawayDirector` · `RunawayState` · `StressGaugeDirector` · `StressGauge`)에 `#if` **0개** — 플랫폼 분기 없음(양성 대조: `StickMateDevTools.cs` 1개).

**잠재 경로(「숫자 하나만」)**: 에셋 `:234`를 `≤1`로 내리면 경로 ①이 살아 있으므로 **즉시** 발동 가능해진다.
이 저장소 거짓 통과 9번 형태 그대로 — **코드 기본값만 고치면 에셋이 덮어서 여전히 죽어 있다.** 되살릴 때는 두 곳을 함께 고친다.

### 판정
1. **자율 발동 OFF = 의도.** 단 **사용자 OFF 요청이 아니라 버그 신고에 대한 리더 수정**이다. 비교:
   `longCapeTripMeanSeconds: 0`은 CLAUDE.md가 *"2026-08-31 사용자 요청 기본 OFF"*로 적는다. 가출 툴팁은 *"사용자 신고 … 직접 원인"*으로 적는다. **성격이 다르다.**
   다만 같은 날 사용자 총평(*"제대로 동작하는게 하나도 없음"*, 요청하지 않은 연출이 캐릭터를 가림)과 방향은 일치한다.
2. **출하 빌드에서 가출 기능 전체가 도달 불가 = 의도 아님.**
   - 이 상태를 **결정한 기록이 0건**이다(`Tasklist.md` · `process.md`에서 `가출`과 `사용자|원문|요청`이 같은 줄에 있는 것은 라이벌 삭제 「보존」 1줄과 오늘 매뉴얼 등재 1줄뿐).
   - 08-29 수정의 전제(*수동 발동 유지*)를 08-31/09-01이 무효로 만들었고, 08-31의 전제(*스트레스의 결과*)는 08-29가 이미 무효로 만든 상태였다. **서로의 전제를 깨고 대조 없이 지나갔다.**
   - 코드 주석도 아직 살아 있는 기능처럼 말한다(§4-4).
3. 그러므로 **"수치 결함"이 아니라 "결정 공백"**이다. 고칠 방향(되살리기/죽은 채 명시/제거)은 **제품 취향이라 사용자만 안다** → §5 질문.

## 3. 발생 빈도 추정 (되살릴 경우의 참고 수치)

### 3-1. 계산기와 교정
`scratchpad/stress_sim.py` — `StressGaugeDirector.cs:129-140, 181-194`의 규칙만 옮긴 거울(창 제거 조건 `now - t > window`, `Clamp01`, 드래그 = 상호작용이므로 감쇠 구간).

| 교정(알려진 값) | 기대 | 결과 |
|---|---|---|
| 창 안 8회 → 0 (`Count > 8`) | 0 | 0 ✅ |
| 창 안 9회 → +0.12 | 0.12 | 0.12 ✅ |
| 창 안 10회(1초 간격) → 0.24 − 감쇠 1초(손계산) | 0.2399861 | 0.239986 ✅ |
| 301초 간격 20회(창 밖) → 0 | 0 | 0 ✅ |
| 방치 12h 경계 | 12.0h | 12.0h ✅ |

★ **교정 1차는 깨졌다.** 9회 기대값을 *"0.12 − 감쇠 1초"*로 적었는데, **0에서의 감쇠는 `Clamp01`로 0에 머문다**(`StressGauge.cs:34-35`).
틀린 것은 계산기가 아니라 **내 기대값**이었고, 그 실행은 교정 실패로 **숫자를 하나도 내지 않고 중단**됐다. 기대값을 고치고, 감쇠가 **실제로 작동하는** 교정(10회)을 추가한 뒤 재실행했다.

| **1.0(원래)** | **5분 창 안 17회**. 간격 무관(1초 간격 16초 · 18초 간격 288초). **간격 ≤ 37.5초**면 도달, **38초면 영원히 0** | **무상호작용 연속 가동 32.0h**(12 + 1.0/0.05) | 발행자 없음 |
| 0.9(UX §24 "예: 90%") | 16회 | 30.0h | 발행자 없음 |

검산: 1.0 ÷ 0.12 = 8.33 → 증가 **9회** 필요(8회 = 0.96) → 8 + 9 = **17회**. 9개 표본이 300초 창에 들어가려면 간격 ≤ 300/8 = **37.5초**.

### 3-3. 해석
- 임계 1.0에서 출하 빌드 가출은 사실상 **"5분 안에 캐릭터를 17번 집어 든다"** 한 가지 원인으로만 난다. 원인이 사용자 행동이라 **원칙 1(결과에 원인이 있다)과는 깨끗하게 맞는다.**
- 방치 32h는 게이지가 저장되지 않아(재실행 시 0) **실사용에서 사실상 안 난다.**
- **실사용 드래그 빈도는 미확인**(분석 전송 0 — `submitAnalytics: 0`). 그래서 "하루 몇 번"은 쓰지 않는다. 행동 조건으로만 적는다.
- 0.9와 1.0의 차이는 드래그 1회뿐 — **임계를 미세 조정할 가치는 없다.** 되살린다면 원래값 1.0이 문서·주석(`RunawayDirector.cs:82`)과도 맞는다.
- ★ **되살리면 예고가 없다.** UX §19·§24의 예고 신호(SULKY · 어깨 처짐)가 둘 다 꺼져 있어(§1-3), 캐릭터가 **아무 조짐 없이** 사라진다 — 08-29 신고(*"안 보이다 클릭하면 나옴"*)가 **그대로 재현될 수 있는 형태**다. 예고를 켜면 이번엔 같은 날 다른 신고(*"몸주위로 이상한 주황색 선들"*)와 부딪힌다.
- 탈출구는 산다: [돌아와!] 칩(`ActionCommandPopover`) · 단축키 N 소환(게이트 밖, `AppControlDirector.cs:673-677`) · 대기 톱니 · 자동 복귀 5400초. **긴급정지 소환은 죽어 있다**(§1-5).

> **(가) 이대로 둔다** — 정식 빌드에는 가출이 없는 것으로 문서를 정리합니다. 코드는 그대로 남깁니다.
> **(나) 다시 켠다** — 5분 안에 캐릭터를 17번 이상 집어 들면 삐져서 숨습니다. 미리 기색을 보이는 연출은 꺼져 있어서 **예고 없이 사라집니다**(8월 29일 증상과 같은 모양). 돌아오게 하는 버튼·단축키·90분 자동 복귀는 있습니다.
> **(다) 설정에서 켜는 사람만** — 기본은 꺼 두고, 설정 창에 「가출」 켜기를 둡니다(켜면 (나)와 같은 조건).
> **(라) 기능을 없앤다** — 코드·대사·번역 문자열까지 걷어냅니다.

작성 `game-architect` · 2026-09-05 · **프로덕션 `.cs` 수정 0건**
근거는 전부 이 날짜에 저장소에서 직접 잰 것이다. 문서에서 베낀 문장은 출처와 함께 표시하고,
**실측과 문서가 갈린 곳은 실측을 적었다**(§0-3에 3건).

> **입력**: 사용자 지시 — 팀 전체 목표를 **「Windows 스팀 출시」**로 좁힌다.
> **제약**: 개발 머신은 macOS. Windows 실기는 사용자의 **낮 시간**에만 열린다.
> **이 문서의 쓸모**: 리더가 다음 라운드에 22명을 재배치할 때 **무엇을 지금 주고 무엇을 낮까지
> 붙들 것인가**를 가르는 표. 전체 목록이 아니라 **순서와 그 근거**가 본체다.

### 0-2. 출시일 공식 — 항 하나가 빠지고 하나가 게이트로 올라간다

```
종전 (ROADMAP §17-3)   출시일 = max( R-2′ , R-6a , R-5-min , W-gate )
전환 후                출시일 = max( R-2′ , R-5-min )        단, W-gate 전량 통과가 「출시 자격」
```

| 항 | 무엇 | 전환 후 |
|---|---|---|
| **R-6a** | macOS Developer ID 서명 + 공증 ($99/년, `notarytool`/`stapler`, `LibUniWinC.bundle` 딥서명) | ★★ **공식에서 빠진다.** 근거였던 *"스팀이 macOS 앱에 공증을 요구한다"*는 **macOS 빌드를 낼 때만** 발동한다. **Windows 단독 출시에는 macOS depot이 없다.** 소관 공백(4회차까지 파이프라인 0건)이 **더 이상 출시를 막지 않는다** — 이번 전환의 가장 큰 일정 이득 |
| **R-5-min** | DLC 6팩 통로 + 엔타이틀먼트 배선 | **지배항 유지.** 그리고 병목이 문서가 짚은 곳이 아니다 → §3 M-1 |
| **R-2′** | 영어 (고유 356 / 총 505) | **유지되나 근거 하나가 죽었다** → §0-3 (3) |
| **W-gate** | CW-1~CW-5 | ★ **항이 아니라 게이트가 된다.** 종전에는 *"못 따라오면 Windows만 뺀다"*가 성립했다. 이제 **W-gate가 실패하면 출시 자체가 없다.** 「조건부 동승자」에서 「유일한 플랫폼」으로 지위가 바뀌었다 |

★ **부수 이득 1건**: ROADMAP §17-5가 *"스팀의 출시일 1회 노출이 macOS 출시일에 소모되고, 그러면
93.95%의 모수가 그 노출을 영원히 못 받는다"*를 **영구 손실**로 규정했다. **전환이 그 손실을 없앤다.**
이제 그 1회를 Windows(93.95%)가 받는다. 이 전환은 일정만이 아니라 **모수 축에서도 개선이다.**

### 0-3. 실측이 문서와 갈린 것 3건

**(1) 출하 exe에 dGPU 패치가 들어 있지 않다 — 그런데 감사 대장은 「구조는 닫혔다」고 적는다.**

```
Builds/Windows/StickMate.exe   SHA-256 = bf64a21a5c91…8c656559   671,744 B   mtime 09-03 08:32
   ↑ WINDOWS_DGPU_REPORT.md §1-1이 기록한 Unity 플레이어 템플릿 해시와 바이트 단위로 동일하다
Assets/Editor/WindowsHybridGpuExportPostprocessor.cs   ← git status: ?? (미커밋 · 미빌드)
```
`PlatformParityAuditTests.cs:3736`은 *"Windows: 빌드 후처리가 PE export 값 두 개를 1 → 0으로 바꾼다.
구조는 닫혔으나 실기 미확인"*이라고 적는다. **소스는 닫혔고 산출물은 안 닫혔다.**
⇒ **지금 존재하는 Windows zip 3개 전부로는 게이트 G1을 잴 수 없다.** §4 H-0.

**(2) 활성 빌드 타깃이 이미 Windows다.**
```
Library/Bee/artifacts/1900b0aE.dag/StickMate.Runtime.rsp   09-03 13:35   UNITY_STANDALONE_WIN
Library/Bee/artifacts/200b0aE.dag/StickMate.Runtime.rsp    09-03 08:09   UNITY_STANDALONE_OSX  (구판)
```
전환에 유리하다 — **타깃 전환(전역 상태 변경)이 필요 없다.** 대신 반대편 사각지대가 생긴다:
지금 러너 초록은 **macOS 절반을 구조적으로 못 본다**. §3 M-12.

**(3) 영어(R-2′)를 떠받치던 논증 하나가 죽었다.**
ROADMAP §18-3은 *"macOS 단독일 때 **영어가 유일하게 남은 모수 확대 수단**이다"*로 영어의 값을 올렸다.
**그 전제(macOS 단독)가 사라졌다.** 영어 자체는 사용자 확정(D-5 «넣는다»)이므로 **내가 뒤집지 않는다.**
다만 `product-strategy`는 **죽은 전제를 인용해 유지하지 말고 근거를 다시 유도해야 한다** — 그 항이
출시일 공식의 지배항 후보이기 때문이다.

## 2. 선결 조건 사슬 — 「A를 안 하면 B가 어떻게 막히는가」

```
H-0 새 Windows 빌드 (dGPU 후처리 포함)
     │   ← 없으면: 낮 세션의 모든 관측이 09-03 08:32 산출물에 대한 것이 된다.
     │              그 사이에 미커밋 318파일 라운드가 있다. 세션 하나가 통째로 무효.
     ▼
0-1 문서 3곳 정정
     │   ← 없으면: 사용자가 "출시 산출물이 아니다"를 읽고 판정 기준을 낮춘다.
     │              「미관이니 넘어가자」가 실제로는 출시 차단 항목이다.
     ▼
H-1 세션 설계 (§5) — 교락 제거 · 음성 대조 · 재시작 예산
     │   ← 없으면: G1이 거짓 통과한다(§5-2). 성공과 실패가 똑같이 생긴 자리다.
     ▼
낮 세션 1회 ── CW-1 · CW-2 · B-2 · A-2 · A-4 · A-7 · dGPU G1/G2 동시 수확
     │
     ▼
W-gate 판정 → 스토어 지원 OS 선언(I-2) → 출시일 확정 입력

──────── 이 사슬과 완전 병렬 (자원이 다르다: 우리 시간 vs 사용자 낮 시간) ────────

M-1 팩 조형 통로 (원칙 4의 구멍)  →  M-2 엔타이틀먼트 배선 설계(I-3)  →  R-5-min 착수
```

★ **병렬성이 이 국면의 핵심 자산이다.** W-gate는 **사용자의 낮 시간**을 쓰고 R-5-min·R-2′는 **우리
시간**을 쓴다. ROADMAP §17-3의 이 관찰은 전환 후에도 그대로 참이고, 오히려 더 중요해졌다 —
**낮 세션을 기다리며 팀을 놀리면 그 시간이 전부 손실**이다.

### ★ I-3 갈림길 답 — **팩당 depot 분리는 지금 하지 않는다** (§13-10)

`product-strategy`의 지적 2건은 **실측으로 옳다**(`PackRegistry.cs:180`의 `Resources.LoadAll`은
`resources.assets` **한 파일**로 구워져 depot으로 못 쪼갠다 / Addressables는 `Packages/manifest.json`에
**없다**, mtime 08-28). 그럼에도 **(가)를 지지한다 — 근거는 일정이 아니라 계약이다**:

1. ★ **depot 부재는 `Unknown`을 만들 수 없다.** 「파일 없음」은 ①안 샀다 ②**샀는데 다운로드 중이다**
   ③**사용자가 속성에서 DLC 체크를 껐다**(스팀 공식 기능) ④검증 중이다 — **넷이 똑같이 생겼다.**
   부재를 `NotOwned`로 읽으면 `PackEntitlementState` 문서가 *"이 계약이 막으려는 사고 그 자체"*라고
   적은 붕괴를 **기본 구현이 저지른다.** Steamworks 어댑터는 *"스팀이 안 떴다"*를 **감지**할 수 있지만
   **부재에는 그 신호가 없다** — (나)는 스팀 의존을 없애는 게 아니라 **정직할 능력을 없앤다.**
2. **사는 것이 거의 없다(실측)**: 아이템 42개 = **67.0 KB** / 팩 하나 ≈ **23 KB** / 빌드 **85 MB**
   = **0.03%.** 게다가 콘텐츠가 없으면 **상점에서 그 팩을 보여 줄 수 없다**(아이콘·이름이 그 에셋 안이다).
3. ★ **리더가 요구한 대체 가능성 — 확보돼 있다.** `IPackEntitlementSource.Query(packId) →
   PackEntitlementState` 하나뿐이고 `PackEntitlements.StateOf`는 **출처를 모른다.** 단조 래치·부정
   캐시 금지도 전부 소비자 쪽에 있다. ⇒ **depot 방식은 구현체를 하나 더 만드는 것이고
   `PackEntitlement.cs`는 한 줄도 안 바뀐다.**
   **단 조건 하나 — 그 구현체는 부재를 `NotOwned`로 쓰면 안 된다. 존재는 `Owned`의 양성 증거로만 쓰고
   부재는 `Unknown`이다.** 이 문장이 없으면 나중에 (나)로 갈 때 **가장 자연스러운 구현이 계약을 깬다.**
4. **지금 치르는 값은 0이다.** §13-3-d의 접속 형태(`cohortId` 조인 · 매니페스트에 에셋 참조 없음)는
   Addressables로 갈아탈 때도 그대로이고, 바뀌는 것은 **로더 한 줄**이다.
   ⇒ **(가)를 택하는 것이 (나)를 막지 않는다.** (나)의 촉발 조건은 **팩 콘텐츠가 무거워질 때**
   (고해상 텍스처·오디오)이지 **엔타이틀먼트가 아니다.**

## 5. 낮 세션 1회 설계 — 여기서 거짓 통과가 난다

**세션의 값은 항목 수가 아니라 「가른 것의 수」다.** 아래 5개를 안 지키면 항목을 다 돌아도 아무것도
못 가른다. 전부 이 저장소가 이미 당한 형태다.

### 5-1. 빌드 도달 확인 — `StickMate.exe` 날짜를 보지 마라
그건 Unity 런처 스텁이다. **`StickMate_Data/Managed/StickMate.Runtime.dll`의 mtime**을 본다.
그리고 **exe의 SHA-256이 `bf64a21a…8c656559`가 **아닌지**** 확인한다 — 같으면 **dGPU 패치가 안 들어간 것**이다.

### 5-2. ★★ G1의 교락 — 성공과 실패가 똑같이 생겼다 (신규 지적)
사용자 기계에는 A/B 실측 때 건 **수동 GPU 선호(「절전」 = `UserGpuPreferences`)가 아직 남아 있을
가능성이 높다.** 그 상태에서 패치된 빌드를 돌리면 **내장 GPU 이름이 뜬다 — 패치와 무관하게.**

> **G1은 이 순서를 지키지 않으면 무효다:**
> 1. Windows 설정 → 그래픽에서 StickMate 관련 항목을 **전부 「Windows가 결정」으로 되돌린다**
> 2. **음성 대조** — **패치 전 빌드**(기존 zip)를 먼저 띄워 로그에 **NVIDIA가 뜨는지 확인한다.**
>    여기서 Intel이 뜨면 **그 뒤 숫자는 전부 폐기**한다(수동 설정이 안 지워진 것이다)
> 3. **패치 후 빌드**를 띄워 Intel이 뜨는지 본다
> 4. **작업 관리자 → 성능 → NVIDIA 사용률·전용 메모리가 0인지 함께 본다** — 이름만 바뀌고
>    dGPU가 켜져 있는 **부분 성공**을 거른다

### 5-3. dGPU와 BitBlt를 같은 실행에서 재지 마라
패치가 GPU를 내장으로 내리면 **BitBlt 복사 비용의 주체가 바뀐다.** 두 변수를 한 번에 바꾸면
어느 것이 효과인지 원리상 못 가른다. **(1) 패치 전 = 기준선 → (2) 패치 후 = dGPU만 바뀐 것 →
(3) 프레임 상한/MSAA** 순서로 한 번에 하나만 움직인다.

### 5-4. 재시작 예산이 세션 시간을 지배한다
`[렌더품질]`은 **프로세스당 1회**, `[렌더진단] ★A/B 요약`은 **시작 후 60초에 한 번만** 찍히고
이후 측정이 멈춘다. ⇒ **장시간 A/B를 그 줄로 재면 반드시 「차이 없음」이 나온다.**
장시간의 유일한 올바른 단위는 **5분 주기 요약 줄**이다.
그리고 **`Player.log`는 껐다 켤 때마다 덮어써진다** — 재시작이 많은 §A·§B·§C는 **구간마다** 발췌를 돌린다.

### 5-5. 실기 인스턴스는 **한 번에 하나**
세이브 파일을 모든 인스턴스가 공유한다. 동시에 여럿 돌면 **진행도가 서로 덮어쓴다** — 화면 문제가
아니라 **사용자 데이터 문제**다. `driver.sh stop`과 전역 `Q`는 여전히 **절대 금지**.

`PlatformParityAuditTests.cs`의 실행되는 `Assert.Ignore`는 **13건**이다(문서 주석 5건 제외).

| macOS `NSSupportsAutomaticGraphicsSwitching` | `:3736` | 듀얼 GPU Intel Mac이 없어 **초록을 만들 수 없다** |

# M11 `모션민감` — 화면 안에서 움직이는 것에 몸이 반응하는 사람

작성: `marketing` R5 2026-09-03 · **접근성 축 신설**

> ### ★ 지갑을 여는 한 문장
> **"「움직임을 줄일 수 있다」가 스토어 페이지에 적혀 있으면 산다 —
> 없으면 값을 묻지도 않고 지나간다."**

---

## 0. ★★ 이 페르소나가 특별한 이유 — **우리 헤드라인이 곧 이 사람의 배제 사유다**

우리가 파는 문장은 이것이다:
> *"넘어지는 장면이 미리 만들어져 있지 않습니다. **매번 다르게 구르고 다르게 착지합니다.**"*

**이 사람에게 그 문장은 「사지 마시오」로 읽힌다.**
전정 민감(vestibular)·광과민 계열에게 **예측 불가능한 주변시야 운동**은 정확한 트리거다.

| | M8 `조용한필요` | **M11 `모션민감`** |
|---|---|---|
| 문제 | **방해받는다**(소리·먼저 나섬) | ★ **몸이 반응한다** |
| 해결 축 | 묵음 · 확률 0 · 말풍선 끄기 | ★ **움직임의 양과 예측 가능성** |
| 우리 상태 | ✅ 전부 해결돼 있다 | ★ **해결된 것이 0이다**(2절) |

★ **M8과 반드시 갈라야 한다.** M8은 우리가 이미 이긴 세그먼트이고,
**M11은 우리가 아직 아무것도 안 한 세그먼트**다. 둘을 합치면 **후자가 전자 뒤에 숨는다.**

---

## 1. 이 사람이 스토어 페이지에서 찾는 것 (순서대로)

1. **"움직임을 줄일 수 있는가"** — 없으면 여기서 끝.
2. **"화면 어디에 나타나는가 — 내가 정할 수 있는가"**
3. **"완전히 끌 수 있는가 · 되돌릴 수 있는가"**
4. 그 다음에야 재미

---

## 2. ★ 실측 — 우리가 지금 줄 수 있는 것과 없는 것

| 이 사람이 필요한 것 | 우리 상태 | 근거 (파일 + 심볼) |
|---|---|---|
| **말풍선 빈도 조절 / 끄기** | ✅ **있다** | `Core/AppSettingsModel.ChatterPercent` (0~`MaxChatterPercent` = 200). **0 = 끄기** |
| **소리 없음** | ✅ **있다**(선택이 아니라 강제) | `ProjectSettings/AudioManager.asset` `m_DisableAudio: 1` |
| **먼저 나서지 않음** | ✅ **있다** | 장난 확률 배포 에셋 **10/10 전부 0** |
| **완전히 숨기고 되돌리기** | ✅ **있다** | `⌃⌥⌘K` (Windows `Ctrl+Alt+Win+K`) — 토글. **실기 검증 대기** |
| **전체화면 앱 위에서 물러남** | ✅ **있다**(등급 1) | `Platform/FullscreenSuspendPolicy` |
| ★ **움직임(모션) 자체를 줄이기** | ★★ **없다** | `ReduceMotion` 계열 심볼 **0건**(양성 대조: 같은 파일에서 `ChatterPercent`는 실제로 잡힌다) |
| ★ **던지기 회전 속도 조절** | ★★ **없다** | `States/ThrowTumbleState.ResolveSpinSpeedDegreesPerSecond` — **220~720°/초**, 파라미터화는 돼 있으나 **사용자 설정 창구가 없다** |
| ★ **캐릭터를 한 자리에 고정** | ★★ **없다**(배회가 기본) | — |

> ### ★★ 결론 — **이 사람에게 팔 수 있는 문장이 지금 하나도 없다**
> 우리가 가진 것(묵음 · 말풍선 끄기 · 숨김)은 전부 **「방해 안 함」** 축이고,
> 이 사람이 찾는 것은 **「움직임의 양」** 축이다. **다른 축이다.**
>
> ⇒ **M11은 오늘 「도달 불가」 세그먼트다.** 그리고 그건 **고칠 수 있는 종류의 불가**다.

## 3. ★ 마케팅의 규율 (지금 당장 적용)

| 규율 | 왜 |
|---|---|
| ★ **이 세그먼트를 겨냥한 문구를 쓰지 않는다** | 지금 쓰면 **거짓 소재**다. 「모션 옵션」이 0건이다 |
| ★ **접근성 태그·문구를 스토어에 달지 않는다** | 근거가 없다 |
| ★ **그러나 헤드라인(2-4절 물리)은 유지한다** | 이 세그먼트를 위해 우리 유일한 차별점을 버리지 않는다. **배제를 인정하는 것이 거짓말보다 낫다** |
| ★ **대신 이미 참인 것은 정확히 적는다** | 묵음 · 말풍선 0% · 한 키 숨김 — **이 셋만으로 걸러지는 사람도 있다** |

## 4. ★ 리더에게 올리는 요청 1건 (나는 우선순위를 정하지 않는다)

> **「모션 줄이기」 스위치 1개의 설계 가치를 판단해 달라.**

- **근거(실측)**: 필요한 재료가 **이미 전부 있다.**
  - 확률값이 전부 에셋 노출(`DefaultStickConfig`의 `ledgeHang` · `hopDown` · `stepUp` · `idleChatter` …)
  - 회전 속도가 **이미 파라미터화**돼 있다(`ResolveSpinSpeedDegreesPerSecond`)
  - 설정창에 **같은 형태의 퍼센트 슬라이더가 이미 있다**(`ChatterPercent` 0~200) — **선례가 내부에 있다**
  ⇒ **새 기계를 만드는 것이 아니라 이미 있는 값들에 창구를 하나 여는 일**로 보인다.
  ★ **다만 구현 규모는 내가 판단할 수 없다 — `coder`/`design-motion` 영역이다.**
- **대가**:
  ① **우리 헤드라인을 사용자가 끌 수 있게 된다.** 「물리가 차별점」인 제품에서 물리를 줄이는 스위치는
     **자기 부정**으로 보일 수 있다.
  ② 설정 항목이 늘어난다(사용자가 확정한 **4탭 구성**에 압박).
  ③ 확률을 낮춘 상태의 캐릭터가 **재미없다**는 별개 리뷰를 만들 수 있다.
- ★ **버리는 조건**:
  ① `design-motion`이 *"확률만 낮추면 움직임이 줄지 않고 **부자연스러워진다**"*고 판정하면 폐기
     (그러면 이건 스위치가 아니라 **별도 모션 세트**이고 규모가 완전히 다르다).
  ② 설정 탭 구성이 이미 잠겼고 **리더가 항목 추가를 닫으면** 폐기.
  ③ ★ **1.0 범위 밖으로 밀리면 이 페르소나는 1.0 대상이 아니다** — 그 판정도 정직한 결론이다.

## 5. ★ 이 페르소나가 **당장** 바꾼 것 1건

`STORE_PAGE.md` 7절 금지 목록에 다음이 들어갈 근거를 제공한다:

- ✗ *"누구나 편하게"* / *"거슬리지 않습니다"* 류의 **포괄적 안심 문구**
  → **거슬리는 사람이 실재하고 우리는 그를 위한 스위치가 없다.**
  「거슬리지 않는다」가 아니라 **「소리를 내지 않고, 말풍선은 0%까지 줄일 수 있고,
  한 키로 완전히 숨길 수 있다」**처럼 **셀 수 있는 사실**로만 쓴다.

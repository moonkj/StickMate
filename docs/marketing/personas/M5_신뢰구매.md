# M5 `신뢰구매` — 자기 컴퓨터에 뭘 올리는지 따지는 사람

작성: `marketing` R3 · 근거: `_시장축_공통실측.md`
★ `MARKET_LANDSCAPE.md`가 지목한 **"권한 0 · 네트워크 0"** 자리를 실제로 사는 사람이다.

## ★ 지갑을 여는 한 문장
> **"돈을 내는 쪽을 산다 — 광고도 계정도 서버도 없다는 뜻이라서. 지불이 곧 '내 데이터가 상품이 아니다'라는 증서다."**

## 1. 한 줄 정체
무료 상주 앱을 **일부러 피한다.** "공짜면 뭔가로 갚아야 한다"를 전제로 산다.
개발자·보안 직군일 수도 있고 아닐 수도 있다 — **직업이 아니라 습관으로 정의되는 세그먼트**다.
설치 전에 권한 요구를 보고, 설치 후에 네트워크를 본다. **그리고 실제로 본다.**

## 2. 지갑의 성질 — 여섯 중 가장 특이하다
| 축 | M5 |
|---|---|
| 무엇에 돈을 내나 | 기능이 아니라 **위험 감소** |
| 유료가 장애물인가 | ★ **아니다. 유료가 근거다.** 가격이 신뢰 신호로 작동하는 유일한 세그먼트 |
| 개수·콘텐츠 | **안 본다** |
| 이탈 | 한 번의 배신으로 끝. 그리고 **그 사람은 글을 쓴다** |

★ 이 세그먼트는 **작지만 리뷰·커뮤니티 영향력이 크다.** 초기 리뷰 20건이 전환율을 정하는 구간에서
이 사람의 리뷰 한 줄은 다른 세그먼트 여러 명분의 값을 한다(**크기 추정은 하지 않았다 — 미확인**).

## 3. ★ "장비 42종이 구매 이유가 되는가"
**무관 — 이 사람은 그 항목을 읽지 않는다.**
읽는 것은 세 줄뿐이다: **권한 / 네트워크 / 무엇을 만지는가.**

## 4. 이 사람이 실제로 확인하는 것과 우리 상태
| 그가 확인하는 것 | 우리 상태 | 소재화 |
|---|---|---|
| macOS 접근성·화면기록 권한 요구 | **없다** | ★★★ `SHOT_LIST.md` **B-1**: 첫 실행을 **무편집 한 테이크**로. **컷이 없다는 사실이 증거다** |
| 창 **제목**을 읽는가 | macOS는 **안 읽는다**(앱 이름과 bounds만) | ★★★ 이 카테고리에서 이 정도로 좁힌 곳이 드물다 |
| 네트워크 | **나가지 않는다.** `submitAnalytics: 0` 확인(`ProjectSettings.asset:93`) + 전송 화이트리스트 비어 있음 + 감사 테스트 | ★★★ **단, 출하 빌드에서 재확인 후에만 말한다**(F-M4) |
| 남의 창·파일을 만지는가 | 이동·삭제·크기변경 API가 **인터페이스에 없다** | ★★ |
| 레지스트리 | 쓰기 API **0건** | ★★ |
| ★ **예외가 있는가** | **있다 — Windows 작업표시줄 자동 숨김 비트 1개** | ★★★ **먼저 말한다.** 이 사람에게는 예외를 **밝히는 것**이 신뢰 신호다 |
| 검사가 진짜인가 | ★ **네거티브 컨트롤이 붙어 있다** — 일부러 위반 코드를 넣으면 빨개진다 | ★★★ **이 세그먼트를 위한 개발일지 1편이 여기서 나온다** |

## 5. ★ 오늘 확정에 대한 반대 입력 — 코드서명
오늘 **코드서명이 「필수」 → 「선택」**으로 내려갔다(MS 스토어 제외의 결과).
**M5에게만은 그 판단이 뒤집힌다.**

- 서명 없는 Windows 실행 파일은 **SmartScreen 경고**를 띄운다.
- 이 세그먼트가 그 경고를 보는 순간, **4절 표 전체가 무효가 된다.**
  "권한 0 · 네트워크 0"을 아무리 정확히 말해도 **OS가 우리를 의심하는 화면**이 먼저 뜬다.
- 즉 코드서명은 M5에게 **기능 비용이 아니라 메시지 비용**이다 — 우리 핵심 메시지를 OS가 반박한다.

> **★ 이건 채널 판단(내 소관 아님)이 아니라 「메시지가 화면에서 반박당하는가」의 문제라
> 마케팅이 올릴 자격이 있는 입력이다.** 판정은 리더·`product-strategy`.
> 나는 비용을 모른다(**미확인**) — 비용 대비 판단은 하지 않는다.

★ 스팀 경유 설치는 스팀 클라이언트가 실행하므로 SmartScreen 경로가 다를 수 있다 —
**이 차이를 나는 실측하지 못했다(미확인).** 확인 전에는 "스팀이라 괜찮다"고 가정하지 않는다.

## 6. 버리는 조건
1. **출하 빌드에서 아웃바운드 연결이 한 줄이라도 관측되면** → 즉사. 그리고 **그 관측을 이 사람이 한다.**
   → 규율: **"네트워크 0"은 출하 빌드 실측 후에만 쓴다.** 지금 문안에는 조건부로만 넣었다.
2. **작업표시줄 예외를 스토어 페이지에서 빠뜨리면** → 즉사 + 부정 리뷰.
   빠뜨리는 것이 숨기는 것으로 읽힌다.
3. 향후 어떤 형태로든 **계정·로그인·원격 설정**이 들어오면 → 세그먼트 소멸.
   ★ **플러그인 봉인(1st-party 전용)은 이 세그먼트에 유리하다** — 남의 코드가 들어올 경로가 없다.

## 7. 대가
- 신뢰 메시지는 **한 번 어기면 회복이 안 된다.** 우리가 이 축을 헤드라인으로 쓰는 순간,
  이후 모든 기능 추가가 **이 약속의 검사를 통과해야** 한다(예: 향후 업데이트 알림조차 네트워크다).
- **즉 이 페르소나를 겨냥하는 것은 제품 로드맵을 묶는 결정이다.** 리더가 그 사실을 알고 택해야 한다.

## 8. 요청 (리더 경유)
- → **기획·총괄 / `product-strategy`**: **코드서명 「선택」 판정에 M5 항목을 재입력**해 달라(5절).
- → **`security`**: 판단 필요 — **출하 빌드에서 아웃바운드 0을 실측하는 절차**가 필요하다.
  그게 있어야 마케팅이 **"네트워크 0"을 조건 없이** 쓸 수 있다. 나는 그 절차를 만들 수 없다.
- → **기획·총괄**: 7절의 뜻을 확인해 달라 — 이 축을 헤드라인으로 쓰면 **로드맵이 묶인다.**

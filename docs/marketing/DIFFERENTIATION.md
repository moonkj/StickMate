# 차별점 — **실측으로 방어 가능한 문장만**

작성: `marketing` R4 2026-09-02 밤 · 입력: `tft-competitive`의 경쟁 제품 **공개 소스 원문** 조사
대조 대상: 우리 코드 (`Platform/`)

> ★ **"우리만 된다"는 쓰지 않는다.** 조사가 보장하는 것은 **"찾지 못했다"**까지다.
> 대신 **양쪽이 실제로 무엇을 하는지**를 나란히 놓는다. 그 대비가 문장보다 강하다.

## 2. 우리 측 사실 — 파일:행

| 성질 | 근거 (파일:행) |
|---|---|
| **하나가 아니라 전부.** 창 목록을 z-order 앞→뒤로 **전수 순회**하고, 각 창의 상단선에서 앞선 창들의 구간을 뺀 **남은 조각마다 발판을 하나씩** 낸다 | `Platform/VisibleTopEdgeSolver.cs:127`(외곽 전수 루프) `:148,162,176,183`(가림 구간 차감). 클래스 문서 *"조각이 여럿이면 조각마다 발판을 하나씩"* |
| **최대화돼 있어도 된다.** 발판 경로에 `WS_MAXIMIZE`/`IsZoomed` 배제가 **없다** | `grep -rn "WS_MAXIMIZE\|IsZoomed" Assets/_Project/Scripts/` = **2건, 둘 다 `WindowsTopmostWatchdog.cs:84,840`의 진단 로그**. 발판 경로 0건 |
| **등록이 필요 없다.** 제목 허용목록이 존재하지 않고, **존재할 수도 없다** — 제목 조회 버퍼가 2글자다 | `Platform/Windows/Win32WindowService.cs:487` `TitleProbeBufferChars = 2` (*"1글자 + 널 종단이면 충분하다"*) |
| **가려진 창은 발판이 아니다** (Shimeji의 반대 방향 정확도) | 같은 `VisibleTopEdgeSolver`. 신고 원문이 클래스 문서 첫 줄에 있다 |
| **실측 경계를 쓴다** — 창 장식(그림자/보이지 않는 여백)이 아니라 시각적 프레임 | `Win32WindowService.cs:359,763` `DWMWA_EXTENDED_FRAME_BOUNDS` |
| **cloaked 창 제외** (가상 데스크톱 반대편·UWP 유령 창) | `Platform/Windows/WindowsFootholdFilter.cs:15,225` |
| **투명·클릭관통 창 제외** ★ 2026-09-02 강화 | 같은 파일 `:136` — `WS_EX_TRANSPARENT`를 **무조건 탈락**으로 승격(리더 승인). `:161-163` 알파 3갈래 |
| **양 플랫폼이 같은 코드를 부른다** | `VisibleTopEdgeSolver`가 플랫폼 중립. 클래스 문서가 "한쪽만 고쳐지는 재발 경로를 없앤다"고 명시 |

## 3. ★ 쓸 수 있는 문장 — 정확한 표현

> ### **"하나가 아니라 전부. 최대화돼 있어도. 등록 없이."**
>
> 열려 있는 창의 **모든** 윗면이 발판이 됩니다. 창이 최대화돼 있어도, 다른 창이 반쯤 가려도,
> 가려지지 않고 남은 만큼이 그대로 발판입니다. **어떤 창을 쓸지 미리 등록할 필요가 없습니다.**

**쓰면 안 되는 변형**

| 금지 | 왜 |
|---|---|
| "우리만 됩니다" | 조사는 "찾지 못했다"까지만 보장한다 |
| "Shimeji는 안 됩니다" | ★ **경쟁 제품을 이름으로 깎지 않는다.** 30년 된 무료 오픈소스이고, 그 커뮤니티가 곧 우리 최대 유입원(M4·M6)이다. **깎는 순간 그 채널이 닫힌다** |
| "창을 발판으로 딛습니다"를 헤드라인으로 | 그건 **카테고리 입장료**다(eSheep·Shimeji·Desktop Mate·PixelPet 전부 한다) |
| 성능 비교 | ★ 우리 GPU 11.1%는 **`dwm.exe` 귀속**, Desktop Mate 50%는 **앱 자체 귀속**. **다른 자로 잰 값이다.** 동일 기준 재측정 전 금지 |

★ **차별점의 진짜 구조는 「무엇을 하는가」가 아니라 「얼마나 촘촘한가」다.**
그래서 이 축은 **글로 설득되지 않고 그림으로만 설득된다** → `CAPTURE_REQUESTS_R4.md` D-1.

## 4. 개발일지에서만 쓸 수 있는 것 (스토어 금지)

| 소재 | 왜 개발일지인가 |
|---|---|
| **"가려진 창은 발판이 아니다"** | 스토어에서는 *"안 되는 것"*으로 읽힌다. 개발일지에서는 **정확도의 증거**다 |
| **사용자 신고 → 플랫폼 중립화 이야기** | `VisibleTopEdgeSolver` 클래스 문서 전체가 그대로 1편 본문이다: *"macOS는 고쳤는데 그 수정이 private 메서드 안에 갇혀 Windows가 재사용할 수 없었다"* |
| **감사 테스트의 네거티브 컨트롤** | *"0건이라 초록"*이 아니라 **"일부러 위반을 넣으면 빨개진다"**까지 검증돼 있다 |
| ★ **경쟁 제품 소스를 읽었다는 사실** | **제품명을 깎지 않고** *"이 문제를 남들은 어떻게 풀었나"* 형식으로만. 이 어조가 아니면 게시 금지 |

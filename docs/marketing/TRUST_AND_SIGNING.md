# 무서명 출시의 홍보 비용 — 그리고 그때 쓸 문장

작성: `marketing` · R5 2026-09-03 · **프로덕션 `.cs` 0줄. 외부 게시 0건.**
전제(리더 확정): **Windows 서명은 첫 업데이트 전까지 연기**(한국 개인에게 $9.99/월 경로가 **없다** —
1차 출처 2곳 일치) / **macOS 서명·공증은 1.0 하드 블로커**(스팀 채널 요구).
근거 창고: `docs/strategy/CHANNEL_PRICING_DECISIONS.md` 10절 · `CLAIM_AUDIT_R5.md` 8-1

> **이 문서가 답하는 것 세 가지** (리더 질문 그대로):
> ① 스팀 단독이면 무서명이 홍보에 **어떤 비용**인가
> ② *"바이러스 아니냐"*가 뜰 **확률**과 그때 **쓸 문장**이 준비돼 있는가
> ③ **불신은 평판과 달리 이월된다** — 그 리스크를 어떻게 다루는가

---

## 0. 결론 네 줄

1. ★★ **가장 큰 비용은 「경고」가 아니라 「실행 차단」이다.** Smart App Control은 **MOTW를 보지
   않으므로 스팀 경유로도 비켜 갈 수 없다.** 경고는 읽고 넘기지만 **차단은 리뷰가 된다.**
2. ★★ **서명해도 첫 경고는 뜬다.** 그러므로 *"서명하면 해결"*은 계획이 아니다. **무서명이든
   서명이든 문장이 필요하다** — 서명은 그 문장을 **덜 자주 쓰게** 해 줄 뿐이다.
3. ★★ **지금 만들어지고 있는 기능이 오탐 표면을 넓힌다.** 우리는 곧 **작업표시줄과 Alt+Tab에서
   스스로를 지운다**. 무서명 + 자기 은폐 + 비문서 API는 **은폐형 악성코드와 행동 서명이 겹친다**(2-2절).
   ★ **정정**: 이 두 파일(`AppSwitcherPresencePolicy` · `WindowsTaskbarButtonRemover`)은 **아직
   커밋되지 않은 미추적 파일**이다(`CLAIM_AUDIT_R5.md` 0-0-C). **「착지」가 아니라 「진행 중」**이고,
   ⇒ **그래서 지금이 이 비용을 저울에 올리기에 가장 좋은 시점이다**(6절 J-1).
4. ★★ **불신 이월의 진짜 경로는 리뷰 점수가 아니라 「검색 결과」다.** 그리고 **F2P가 그 유입을
   증폭한다** — 무료라 설치가 많고, 무료라 환불이 없어 불만이 전부 리뷰로 간다(4-1절).

## 1. ① 무서명의 홍보 비용 — **네 갈래로 갈라서 센다**

리더 질문의 전제(*"스팀 단독이면"*)를 그대로 받아 **스팀 경유 설치**만 놓고 잰다.

| # | 경로 | 스팀 단독에서 실제로 걸리는가 | 홍보 비용 |
|---|---|---|---|
| **A** | **SmartScreen 다운로드 경고** | **대체로 안 걸린다.** 스팀 클라이언트가 자체 다운로더로 받으므로 MOTW가 붙지 않는다 ★ **단 "스팀이 MOTW를 안 붙인다"는 1차 출처가 없다 — 미확인** | **낮음** |
| **B** | ★★ **Smart App Control (SAC)** | ★ **걸린다.** *"Smart App Control signature checks apply to **all executable files, not just those downloaded from the Internet**"* — **MOTW를 안 본다.** 무서명 파일은 **긍정 평판이 없으면 실행이 차단**된다 | ★★★ **가장 크다 — 경고가 아니라 실행 실패다** |
| **C** | **백신 오탐** | ★ **구조적으로 노출돼 있다.** 2-2절에서 우리 자신의 API 표면을 셌다 | ★★ **큼. 특히 국내** |
| **D** | **손 배포**(프레스 키 zip · 개발일지 데모 · 베타 테스터) | ★ **전부 걸린다.** MOTW가 붙고 무서명은 *"Strong SmartScreen block"* | ★★★ **하는 순간 즉시.** → 3절 |

### 1-1. ★ 「경고」와 「차단」을 절대 같은 칸에 적지 마라

이 구분이 이 문서의 핵심이다.

| | 경고(A) | **차단(B·D)** |
|---|---|---|
| 사용자가 보는 것 | *"알 수 없는 게시자"* → **[추가 정보] → [실행]** | **실행이 안 된다** |
| 사용자가 하는 것 | 대부분 넘긴다 | **포기하거나 리뷰를 쓴다** |
| 우리 문장이 할 수 있는 일 | 미리 알려 두면 마찰이 거의 0이 된다 | ★ **문장으로 못 고친다. 서명만 고친다** |

⇒ **B가 실제로 얼마나 흔한지가 Windows 서명 연기 판정의 유일한 변수다.**
★ **SAC가 켜져 있는 기기 비율은 Microsoft가 공개하지 않는다 — 미확인.** 숫자를 지어내지 않는다.
다만 MS 지원 FAQ가 *"Recent Windows updates allow Smart App Control to be enabled without
requiring a clean installation"*이라고 적어 **모수가 넓어지는 방향**임은 시사한다.

### 1-2. ★ 서명해도 사라지지 않는 것 (거짓 소재 방지)

> **`Valid Certificate (OV/EV)` → `⚠️ Warning — app flagged as unrecognized until reputation
> accumulates; verified publisher name is displayed`** — Microsoft Learn

**서명해도 첫 경고는 뜬다.** 그러므로 아래 문구는 **금지**다(스토어 페이지 7절에 등재했다):

- ✗ *"서명되어 있어 경고가 안 뜹니다"*
- ✗ *"인증된 앱입니다"*

**서명이 실제로 사는 것은 둘뿐이다:**
1. 경고 화면에 **퍼블리셔 이름**이 뜬다(무서명은 *"알 수 없는 게시자"*).
2. ★★ **버전을 넘어 평판이 이어진다** — *"Unsigned files must build reputation anew with
   every update."*

> ### ★★ 2번이 이 제품에 특히 아프다
> **상주 앱은 업데이트가 잦다.** 무서명이면 **릴리스마다 평판이 0으로 리셋**된다.
> 즉 무서명의 비용은 **출시 1회의 비용이 아니라 릴리스마다 반복되는 비용**이다.
> ⇒ **리더 판정(「첫 업데이트 전까지 연기」)과 정확히 맞물린다** — 그 판정의 진짜 뜻은
> *"평판을 쌓기 시작하기 전까지만 미룬다"*이고, **두 번째 릴리스부터는 미루는 것의 비용이 커진다.**

## 2. ② *"바이러스 아니냐"*가 뜰 확률 — **숫자를 지어내지 않고 노출 요인을 센다**

★ **확률을 모른다.** 이 카테고리의 리뷰에 그 말이 뜬 비율에 대해 나는 1차 출처가 없다.
**그래서 확률 대신 「구조적 노출 요인」을 세고, 그중 우리에게 해당하는 것을 실측했다.**

### 2-1. 이 카테고리 자체의 노출 요인

| 요인 | 우리 |
|---|---|
| 상주(24시간 백그라운드) | ★ 해당 |
| 항상 위 + 반투명 오버레이 | ★ 해당 |
| **다른 앱의 창을 열거한다** | ★ 해당 |
| 무료 | ★ 해당 (F2P 확정) |
| 무서명(Windows) | ★ 해당 (1.0) |
| 광고 SDK 포함 | ✗ 해당 없음 — **우리가 이길 수 있는 유일한 칸** |

### 2-2. ★★ 우리 Windows API 표면 — **어젯밤에 넓어졌다** (실측)

`Assets/_Project/Scripts/Platform/Windows/**` P/Invoke 전수(테스트 제외). **양성·음성 대조 포함.**

| 우리가 실제로 부르는 것 | 무엇으로 읽히는가 |
|---|---|
| `EnumWindows` · `GetWindowRect` · `GetTopWindow` | 창 열거 |
| `OpenProcess` · `QueryFullProcessImageNameW` · `ProcessIdToSessionId` | **프로세스 열거** |
| `RegOpenKeyExW` · `RegEnumKeyExW` · `RegQueryValueExW` | **레지스트리 읽기** |
| `GetAsyncKeyState` | **전역 키 상태 폴링** |
| `SetWindowLong` · `WS_EX_LAYERED` · `SetLayeredWindowAttributes` | 레이어드 창 조작 |
| `SHAppBarMessage` | **셸 앱바 메시지**(승인된 예외 1건) |
| ★ `InternalGetWindowText` | ★ **비문서 API** |
| ★ `WS_EX_TOOLWINDOW` (`WindowsToolWindowStyleControl`) | ★ **Alt+Tab에서 자기를 지운다** |
| ★ `ITaskbarList::DeleteTab` (`WindowsTaskbarButtonRemover`) | ★ **작업표시줄에서 자기를 지운다** |

**★ 안 부르는 것(음성 대조 — 이게 우리를 구한다)**

| 니들 | 결과 | 확인 방법 |
|---|---|---|
| `CreateRemoteThread` | **0건** | 전수 grep |
| `VirtualAllocEx` / `WriteProcessMemory` | ★ **실호출 0건.** 매치 2건은 **「우리는 이걸 안 한다」고 적은 주석**이다 | ★ 매치를 눈으로 열어 확인했다 — **개수만 세면 반대로 읽힌다** |
| `SetWindowsHookEx` | ★ **실호출 0건.** 매치 1건은 *"후킹이나 관리자 권한도 필요 없다"*는 주석 | 같은 방법 |
| 레지스트리 **쓰기**(`RegSetValueEx`/`RegCreateKeyEx`/`RegDeleteKey`/`RegDeleteValue`) | ★ **실호출 0건.** 매치 2건은 *"선언조차 하지 않는다"*는 주석 | 같은 방법 |
| 합성 입력 7종(`SendInput`/`keybd_event`/… ) | **0건** | R4 실측, 이번 유지 |
| ★ **양성 대조** | `RegQueryValueExW`(읽기)는 **3건 실호출** | 프로브가 살아 있음 |

> ### ★★ 그래서 이번 라운드의 새 사실
> **우리는 지금 「작업표시줄과 Alt+Tab에서 자기 자신을 지우는 기능」을 넣고 있다**
> (★ **미커밋 · 진행 중** — 그래서 되돌리기가 아직 싸다).
> 그 자체는 정당하다 — macOS가 이미 하는 것(`NSApplicationActivationPolicyAccessory`)과의
> 대칭이고, `⌃⌥⌘K`의 존재 이유(화면공유 중 나오지 마)와도 맞물린다.
>
> **그러나 신뢰의 관점에서는 다르게 읽힌다**:
> `무서명` + `상주` + `프로세스/창/레지스트리 열거` + `전역 키 폴링` + `비문서 API` +
> **`작업 전환기에서 자기 은폐`** — 이 조합은 **은폐형 악성코드의 행동 서명과 겹친다.**
>
> ⇒ **이건 기능을 되돌리자는 말이 아니다.** 두 가지를 하자는 말이다:
> **(가)** Windows 서명 연기 판정의 **비용 항목에 이 조합을 추가**해 리더가 다시 저울에 올린다.
> **(나)** **매뉴얼과 스토어 페이지가 이 은폐를 먼저 말한다.** 우리가 안 말하면
> 발견한 사람이 말하고, 그때는 *"숨기려던 걸 들켰다"*가 된다.
>
> ★ 그리고 저장소가 이미 그 필요를 적어 두었다 — `AppSwitcherPresencePolicy` 클래스 문서:
> *"갚아야 할 대가 (매뉴얼에 반드시 들어간다) … 그 문장이 매뉴얼에 없으면 이 변경은 사용자를 가둔다."*

### 2-3. ★ 국내 가중치 — 사용자 환경이 이미 알려져 있다

커밋 `aaac7b2` 기록: **사용자 환경 = V3 백신.**
국내 배포에서 **V3 · 알약 계열의 휴리스틱**은 서구권 엔진과 다른 판단을 낸다(★ 이건 **직관**이고
비교 데이터가 내게 없다 — **미확인**). 다만 **위 2-2절 조합이 휴리스틱 표적이라는 것은 구조적 사실**이고,
**무서명이 그 판정을 나쁜 쪽으로 민다**는 것도 구조적이다.

⇒ **국내 커뮤니티 반응(F-3)은 스팀 리뷰보다 먼저 올 가능성이 높다.** 그쪽 문장이 3절에 있다.

## 3. ★★ 자동 앞당김 조건 — **마케팅이 바로 그 방아쇠를 당길 수 있는 자리에 있다**

리더 확정: **스팀 밖 직배포를 하는 순간 서명이 앞당겨진다**(itch.io · 홈페이지 zip · 디스코드).
MOTW가 붙고 무서명은 *"Strong SmartScreen block"*.

> ### ★★ 이 조건에 가장 먼저 걸리는 사람은 **나(마케팅)**다
> 마케팅이 평범하게 하는 일 중 **아래 넷이 전부 「스팀 밖 직배포」다**:
>
> | 마케팅 활동 | 서명 방아쇠인가 |
> |---|---|
> | 프레스/스트리머에게 **빌드 zip**을 보낸다 | ★ **그렇다** |
> | 개발일지에 **체험판 링크**를 건다 | ★ **그렇다** |
> | 디스코드/커뮤니티에 **베타 빌드**를 올린다 | ★ **그렇다** |
> | itch.io에 **미러**를 둔다 | ★ **그렇다** |
> | 스팀 **키**를 나눠 준다 | **아니다** — 스팀 경유다 |
>
> ⇒ **규율 T-1(이 문서의 구속력 있는 규칙)**:
> **`marketing`은 스팀 밖으로 실행 파일을 내보내는 어떤 계획도 세우지 않는다.**
> 필요하면 **스팀 키**를 쓴다. zip을 보내야 하는 상황이 생기면 **그 자리에서 리더에게 올린다** —
> 그건 홍보 결정이 아니라 **서명 예산 결정**이기 때문이다.
>
> ★ **macOS는 더 단호하다**: 애드혹 서명(`codesign` 실측: `Signature=adhoc`, `TeamIdentifier=not set`)은
> `com.apple.quarantine`이 붙는 순간 **그 자리에서 막힌다.** macOS 빌드를 손으로 한 번이라도
> 배포하면 **그날 Developer ID가 필요해진다.**

## 4. ③ 불신 이월 — **가장 위험한 경로는 리뷰 점수가 아니다**

### 4-1. ★ F2P가 이월을 증폭한다 (v2 신규 분석)

| 축 | 유료였다면 | **무료(확정)** |
|---|---|---|
| 설치 수 | 적다 | **많다** — 신뢰 질문의 절대 수가 커진다 |
| 불만의 배출구 | **환불**(2시간 내, 조용함) | ★ **환불할 것이 없다 → 전부 리뷰로 간다** |
| 잘못 온 사람 | 페이지에서 걸러진다 | ★ **안 걸러진다** (한국어 전용인데 영어권이 설치) |
| 첫 리뷰가 쌓이는 속도 | 느리다 | ★ **빠르다 — 초기에 굳는다** |

★ *"무료 제품은 환불이 없어 불만이 리뷰로 간다"*는 **스팀 환불 정책의 구조에서 따라오는 추론**이다.
**비율 통계에 대한 1차 출처는 내게 없다 — 미확인.**

### 4-2. ★★ 진짜 이월 경로는 **검색 결과**다

스팀 리뷰는 개인이 수정·삭제할 수 있고, 「최근」과 「전체」가 분리돼 있다.
**그러나 다음 세 가지는 우리가 손댈 수 없고 검색엔진에 오래 남는다:**

1. **커뮤니티 게시글 제목** — *"StickMate 바이러스인가요?"* 형태의 질문 글.
   ★ **답이 달려 해결돼도 제목은 그대로 남는다.** 그리고 사람들은 제목만 본다.
2. **백신 벤더 오탐 DB 캐시** — 오탐이 해제돼도 스크린샷은 남는다.
3. **첫 리뷰에 박힌 문장** — 나중에 서명해도 그 리뷰는 안 지워진다(리더 지적 그대로).

> ★ **그래서 이 문제의 유일한 실효 대책은 「빨리 대응하는 것」이 아니라 「먼저 말해 두는 것」이다.**
> 사후 해명은 **그 질문 글을 하나 더 만들 뿐**이다.

### 4-3. ★ 처방 — **우리가 먼저 낸다** (선제 문서)

| # | 무엇 | 근거 | 대가 | ★ 버리는 조건 |
|---|---|---|---|---|
| **T-A** | **스토어 페이지에 무서명 한 줄**(4절 문안) | 미리 알려 두면 A(경고)의 마찰은 거의 0이 된다. B(차단)는 못 고치지만 **"몰랐다"는 없앤다** | 페이지에 부정적 문장을 자진해 넣는 비용 | 서명이 1.0에 들어가면 문장을 교체한다(삭제가 아니다 — 1-2절대로 경고는 여전히 뜬다) |
| **T-B** | ★ **다중 엔진 스캔 결과를 우리가 먼저 게시** | 근거를 **1차 자료로** 만든다. 질문이 오기 전에 링크가 존재하면 커뮤니티 글이 **덜 생긴다** | ★★ **파일이 공개된다.** 출시 **전** 빌드를 올리면 유출이다 → **공개 릴리스 빌드에만.** 그리고 **오탐이 실제로 나오면 그 결과가 우리 손에서 공개된다** | ★ **스캔에서 탐지가 0이 아니면 이 전략은 역효과다.** 그때는 폐기하고 **서명을 앞당긴다**(리더 판정 필요) |
| **T-C** | **매뉴얼에 「보이지 않을 때 찾는 법」** | 우리는 이제 작업표시줄·Alt+Tab에서 자기를 지운다(2-2절). **찾는 단서가 사라진다** | 매뉴얼 분량 | `AppSwitcherPresencePolicy`의 은폐를 되돌리면 불필요 |

★ **T-C는 이미 저장소가 답을 갖고 있다**: `_userHidden`은 **세이브에 없다** — **재실행하면 숨김이
반드시 풀린다**(`AppSwitcherPresencePolicy` 클래스 문서). 이 한 문장이 매뉴얼에 있어야 한다.
→ `perf-doc`(문서화)에 **리더 경유** 전달 요청.

## 5. ★★ 준비된 문장 — **지금 쓴다. 나중에 쓰지 않는다**

**전부 초안이고, 게시는 리더 승인 후 사용자가 한다.**
★ 각 문장에 **「어디에 쓰는가」**와 **「무엇이 참이어야 쓸 수 있는가」**를 붙였다.

### 5-1. 스토어 페이지 한 줄 (Windows 1.0, 무서명 시점)

| 한국어 | English |
|---|---|
| **Windows에서 처음 실행할 때 「알 수 없는 게시자」 경고가 뜰 수 있습니다.** 아직 코드 서명 인증서를 사지 않았기 때문이고, 앱이 하는 일과는 관계가 없습니다. 이 앱이 무엇을 읽고 무엇을 쓰지 않는지는 위 목록에 전부 적어 두었습니다. | **Windows may show an "unknown publisher" warning the first time you run it.** That's because we haven't purchased a code-signing certificate yet — it says nothing about what the app does. Everything it reads, and everything it refuses to touch, is listed above. |

★ **쓸 수 있는 조건**: **Windows가 실제로 무서명으로 나갈 때만.** 서명이 1.0에 들어가면 이 문장은
거짓이 되므로 **반드시 교체**한다(1-2절 — 서명해도 경고는 뜨므로 문장은 남되 이유가 바뀐다).
★ **쓰면 안 되는 것**: *"안전합니다"* — 우리가 우리를 안전하다고 말하는 것은 근거가 아니다.
**대신 목록을 가리킨다.**

### 5-2. *"바이러스 아니냐"* 질문에 대한 답 (커뮤니티·리뷰 답글)

> **"서명 인증서를 아직 안 샀습니다. 그래서 Windows가 「알 수 없는 게시자」라고 말합니다.
> 그 경고는 「이 앱이 나쁘다」가 아니라 「누가 만들었는지 확인할 수 없다」는 뜻입니다.**
>
> **앱이 실제로 무엇을 하는지는 확인하실 수 있게 적어 두었습니다 —
> 창 목록과 위치는 읽고, 창 제목은 읽지 않으며(Windows에서 그 확인에 쓰는 버퍼가 1글자입니다),
> 레지스트리에는 쓰지 않고, 마우스·키보드를 대신 눌러 주지 않습니다.
> 접근성·화면 기록·관리자 권한을 하나도 요구하지 않는 것도 그래서입니다.**
>
> **인증서는 [계획 시점]에 넣을 예정입니다."**

★ **이 문장이 강한 이유는 「안전하다」고 말하지 않기 때문이다.**
**검증 가능한 사실 네 개**를 말하고, 그 넷은 전부 **자동 감사가 지키고 있다**
(`OfflineFirstNetworkAuditTests` / `UserAssetImmutabilityAuditTests` — **네거티브 컨트롤 포함**).

★ **쓸 수 있는 조건 — 문장별로 다르다**:
- 「창 제목 안 읽음」 ✅ 양 플랫폼 실측 완료
- 「레지스트리에 안 씀」 ✅ 실호출 0건 + 양성 대조
- 「합성 입력 없음」 ✅ 7종 0건
- 「권한 0」 ✅ 권한 API 0건 + 양성 대조 2종
- ✗ **「인터넷에 안 나갑니다」는 이 답글에 넣지 마라** — 아직 실측 전이다(`CLAIM_AUDIT_R5.md` 6절).
  ★ **그리고 이 답글은 의심하는 사람이 읽는 글이다.** 여기서 한 줄이 틀리면 **나머지 네 줄까지
  같이 죽는다.** 확실한 것만 쓴다.

### 5-3. 「작업표시줄에 안 보인다」에 대한 답 (선제 — 매뉴얼 + 페이지)

> **"작업표시줄과 Alt+Tab에는 나타나지 않습니다. 발표나 화면 공유 중에 우리 이름이
> 남의 화면에 찍히지 않게 하려는 것입니다(macOS에서는 처음부터 그랬습니다).
> 그래서 창을 찾는 평소 방법이 통하지 않습니다 —
> 숨겼다면 `Ctrl+Alt+Win+K`로 되돌리고, 그것도 안 되면 **앱을 다시 실행하면 숨김이 반드시 풀립니다.**"**

★ **마지막 문장의 근거**: `_userHidden`은 세이브에 없다(`CharacterSaveStore`가 이 필드를 한 번도
읽거나 쓰지 않는다). ★ **이 문장은 코드가 바뀌면 즉시 거짓이 된다** — `_userHidden`이 세이브에
들어가는 순간 폐기하고 문장을 다시 쓴다.
★ **쓸 수 있는 조건**: **Windows 실기 확인 후.** 지금은 실기 0회다(`CLAIM_AUDIT_R5.md` 8-1).

## 6. 리더에게 올리는 판단 3건 (나는 결정하지 않는다)

| # | 판단 | 내가 붙이는 근거 |
|---|---|---|
| **J-1** | **Windows 서명 연기 판정의 저울에 「자기 은폐 + 비문서 API」를 추가할 것인가** | 어젯밤 착지로 API 표면이 넓어졌다(2-2절). 연기 판정은 그 이전 상태에서 내려졌다 |
| **J-2** | **T-B(선제 스캔 게시)를 할 것인가** | 근거를 1차 자료로 만들 수 있는 유일한 수단. **대가는 파일 공개**이고 **버리는 조건은 탐지 ≠ 0** |
| **J-3** | **T-A(스토어 무서명 한 줄)를 1.0 페이지에 넣을 것인가** | 넣으면 페이지에 부정적 문장이 자진 등장한다. 안 넣으면 **경고를 처음 본 사람이 커뮤니티에 묻는다** — 그 글 제목이 4-2절의 영구 자산이 된다 |

★ **내가 권고하는 것은 J-3 「넣는다」 하나뿐**이다. 근거: 이 페이지에는 이미
**「하지 않는 것」 목록**이 본문으로 서 있고(스토어 v2 4절), **그 목록의 신뢰가 이 한 줄로 완성된다** —
*"불리한 것도 먼저 적는 곳"*이라는 증거가 되기 때문이다. J-1·J-2는 **비용과 유출이 걸려 리더 판정**이다.

## 7. 플랫폼 영향

- **Windows 영향: 함께 검토함(문서만).** 이 문서의 대부분이 Windows 건이다 —
  ① SAC는 MOTW를 안 봐서 **스팀 경유로도 안 비껴간다**(1절 B).
  ② 무서명은 **릴리스마다 평판 리셋** → 상주 앱에 특히 비싸다(1-2절).
  ③ **API 표면이 어젯밤 넓어졌다**(2-2절, 실측 + 음성 대조).
  ④ 스토어 문장·커뮤니티 답글·매뉴얼 문장 **3벌을 미리 준비했다**(5절).
  ★ 전부 **Windows 실기 0회** 상태의 판단이며, 현행 배포본(12:42)에는 관련 코드조차 없다.
- **macOS 영향: 함께 검토함(문서만).** 서명·공증이 **1.0 하드 블로커**라 페이지 시점에는 이미
  서명돼 있고 **무서명 문장이 필요 없다.** 단 **애드혹 상태에서 손 배포하면 그날 막힌다** —
  `codesign` 실측(`flags=0x2(adhoc)` / `TeamIdentifier=not set`)이 그 근거이며,
  그래서 **규율 T-1(스팀 밖 배포 금지)은 macOS에 더 강하게 적용된다**(3절).

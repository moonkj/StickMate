## 0. 먼저 — 리더가 판단해야 할 두 가지

### 0-1. ★ 빌드가 갈라져 있다 (촬영 순서를 결정한다)

`CLAIM_AUDIT_R4.md` 2절 바이트 실측:

| | macOS **19:07** | Windows **12:42** |
|---|---|---|
| 등급 1(패널 회수) | **있다** | **없다** |
| 숨김 단축키 ⌃⌥⌘K | **있다** | **없다** |

→ **P1·P2는 macOS에서만 찍을 수 있다.** Windows로 찍으면 **거짓 소재**다.
→ Windows 재빌드가 없으면 **Windows 회차를 아예 열지 않는 편이 안전하다.**

### 0-2. 깨끗한 캡처 환경이 아직 없다

`CAPTURE_PROTOCOL.md` 1절. **사용자 실사용 화면은 소재로 쓸 수 없다** — 남의 창 제목·파일명이 찍힌다.
→ 아래 전 항목의 **공통 선행 조건**이다. 별도 계정 / 빈 바탕화면 / 지정한 창만 열린 상태.

## 4. 플랫폼 영향
- **Windows 영향: 별도 배정 필요(사유: 실기 환경 부재 + 배포본 낡음).**
  이 개발 머신에 Windows 실행 환경이 없고, 현행 배포본에 P1·P2 코드가 없다.
  **Windows 회차는 재빌드 뒤 사용자가 촬영**해야 한다.
- **macOS 영향: 없음(문서만).** 1~5회차는 이 머신에서 가능하지만 **깨끗한 캡처 환경이 아직 없고**,
  실기는 순번제라 **리더 배정 없이는 실행하지 않는다.**

실기는 순번제이고 지금 다른 라운드 차례다(`docs/TEAM.md` 「실기 테스트는 한 번에 하나」).

## 0. 먼저 — 리더가 판단해야 할 두 가지

### 0-1. ★ 빌드가 갈라져 있다 (촬영 순서를 결정한다)

`CLAIM_AUDIT_R4.md` 2절 바이트 실측:

| | macOS **19:07** | Windows **12:42** |
|---|---|---|
| 등급 1(패널 회수) | **있다** | **없다** |
| 숨김 단축키 ⌃⌥⌘K | **있다** | **없다** |

→ **P1·P2는 macOS에서만 찍을 수 있다.** Windows로 찍으면 **거짓 소재**다.
→ Windows 재빌드가 없으면 **Windows 회차를 아예 열지 않는 편이 안전하다.**

### 0-2. 깨끗한 캡처 환경이 아직 없다

`CAPTURE_PROTOCOL.md` 1절. **사용자 실사용 화면은 소재로 쓸 수 없다** — 남의 창 제목·파일명이 찍힌다.
→ 아래 전 항목의 **공통 선행 조건**이다. 별도 계정 / 빈 바탕화면 / 지정한 창만 열린 상태.

## 2. 찍지 말 것 (이번 회차 명시적 제외)

| 제외 | 왜 |
|---|---|
| **Windows에서 P1·P2** | 12:42 빌드에 그 코드가 없다. 찍히는 것은 **옛 동작**이다 |
| **성능 계측 화면** | 재측정+승인 전 금지. ★ 경쟁 비교는 **귀속 기준이 다르다**(dwm.exe vs 앱 자체) |
| **"네트워크 0" 계측기 화면** | `security`의 출하 빌드 아웃바운드 실측 절차가 **선행**이다. 그리고 스토어 금지·개발일지 전용 |
| **장비·색 관련 일체** | D등급 |
| **격파 놀이 / 이벤트 탭 / 모바일** | 존재하지 않는다 |
| **레벨 30 저장 파일로 찍은 보관함을 캡션 없이** | 신규 설치 화면은 `???` **35칸**이다. 캡션 병기 필수 |

## 3. 촬영 회차 제안 (리더가 순번에 넣을 단위)

| 회차 | 항목 | 필요 상태 | 소요 추정 |
|---|---|---|---|
| **1회차 (macOS)** | **P1 · P2 · P2b** | 신규 저장 + 전체화면 앱 1개(게임 아님) | 짧다. **가장 먼저** — 오늘 풀린 게이트다 |
| 2회차 (macOS) | P3 · P11 · P6 | 창 4개 배치 고정 | 중간 |
| 3회차 (macOS) | P4(8테이크) | 시간 여유 — 물리라 대기 | 길다 |
| 4회차 (macOS) | P5 · P8 · P9 · P10 | 행동 확률 수동 | 중간 |
| 5회차 (macOS) | P7 · P13 | 깨끗한 계정 | 길다 |
| **Windows 회차** | P3 · P5 · P7 · P8 · P9 · P12 | ★ **재빌드 후**. 촬영 주체는 사용자 | 별도 배정 필요 |

★ **한 회차에 하나의 인스턴스만.** 끝나면 자기 PID만 정리한다.
`driver.sh stop`과 전역 `Q`는 **금지**(사용자 인스턴스까지 죽는다).

## 4. 플랫폼 영향
- **Windows 영향: 별도 배정 필요(사유: 실기 환경 부재 + 배포본 낡음).**
  이 개발 머신에 Windows 실행 환경이 없고, 현행 배포본에 P1·P2 코드가 없다.
  **Windows 회차는 재빌드 뒤 사용자가 촬영**해야 한다.
- **macOS 영향: 없음(문서만).** 1~5회차는 이 머신에서 가능하지만 **깨끗한 캡처 환경이 아직 없고**,
  실기는 순번제라 **리더 배정 없이는 실행하지 않는다.**
